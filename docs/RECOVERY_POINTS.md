# 存档盒的自动恢复点（2026-10-24）

## 怎么找回

打开外壳外的「存档盒」，选择「自动恢复点 · 查看」。列表按新到旧展示最多 10 份恢复点，包含生成时间、伙伴、种类、已保存的成长阶段和最后记录时间。

选择「预览这份恢复点」只读取原始存档，不会立刻覆盖。LCD 沿用备份确认页：**B 确认整份替换，A / C 取消**。确认前建议先导出当前存档。小游戏、照顾和确认仍只使用机身三键，LCD 没有新增按钮或输入框。

恢复点是在旧档迁移、导入或重新开始之前保留的原始内容，**不是定时备份，也不是云备份**。生成时间与其中的最后记录时间可以不同。数据库未保存每份恢复点的触发原因，因此列表不会推测它来自哪一种操作。恢复点和当前存档都在同一台服务的 SQLite 数据库中，不能替代自己留存的 JSON 备份。

## 预览与替换的边界

- 浏览列表和读取选中的内容不迁移、不结算、不领取回访小结，也不写入当前存档。旧档缺少成长记录时显示「旧档阶段待迁移」，不会提前推算成年形态。
- 损坏内容、未知字段或未来版本、超过 64 KiB 的内容不会提供恢复按钮；原始恢复点仍按现有保留规则保存。恢复点记录时间超前时，先校准服务时钟再重新读取。
- 选中的恢复点在读取前若已被最近 10 份的保留规则清理，会明确提示不存在，不换成另一份。读取失败只提供手动重试，没有自动导入或重发。
- 真正确认沿用 `/api/import` 的严格校验、旧档迁移、最多 12 小时离线结算、存档代次检查和事务保护。其他页面替换当前存档会作废旧确认；即使尚未收到页面同步，服务端也会拒绝过期代次。
- 替换前会再保留当前存档的原始内容，同时只保留最近 10 份恢复点。恢复后可从列表找到被替换的当前存档，前提是它仍未被后续操作清理且可通过校验。
- 未完成小游戏按原导入规则结束，不发完成奖励。取消预览不会自动继续小游戏，也不会冻结正常时间流逝和既有轮询。
- 当前存档内容损坏但数据库仍能打开时，可查看健康恢复点并手动确认修复。数据库文件整体损坏、服务无法连接、写结果尚未核对或当前存档存在时钟异常时，不开放此入口来绕过保护。

## 实现与验证

只新增只读 `GET /api/snapshots` 和 `GET /api/snapshots/{id}`，响应禁止缓存。编号使用十进制字符串，避免 JavaScript 对大整数取整。确认仍使用既有导入接口，没有新存档字段或数据库结构，也没有直接恢复的写接口。

新增存储、HTTP 和前端回归覆盖：只读与原字节保留、旧档、损坏当前内容、不可用恢复点、未来时钟、十份保留、精确编号、过期代次、取消和单次确认、迟到响应、超时和手动重试、暂停对局取消，以及 LCD 三键边界。

真实浏览器回归 `scripts/check-recovery-points.mjs` 使用临时数据库、随机端口和隔离构建。覆盖四种桌面／320px／双倍字号／短屏强制颜色配置中的只读浏览、键盘预览、取消、确认、恢复后刷新与当前内容快照；另验证清理后的选中项和跨客户端过期确认。数据为构造测试存档，视口测试不代表实体手机或真人读屏验收。

```sh
PIXELPET_TEST_BINARY=/absolute/path/to/isolated-pixelpet \
PIXELPET_TEST_WEB=/absolute/path/to/isolated-web-build \
PIXELPET_PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs \
node scripts/check-recovery-points.mjs
```
