# 棋盘自动节拍中的 C 暂停

[文档导航](README.md) · [贪吃蛇](SNAKE.md) · [俄罗斯方块](TETRIS.md)

## 问题与操作约定

贪吃蛇与方块由服务端确认每次自动移动／下落。原来等待回复时三个按键一起锁住；请求已持锁、React 尚未更新按钮的间隙，点到 C 也会被忽略。这不是离线补跑或棋盘数据错误，而是自动节拍的输入窗口问题。

现在仅自动 `snake-step`／`tetris-step` 请求允许 C 暂停：

1. 立即取消本地运行许可，显示原有暂停界面；清掉尚未发送的蛇转向、将方块菜单回到「继续」。
2. 不与在途步进并发写暂停，连续 C 合并成一次意图；等待期间 A/B 不排队。
3. 步进成功、回复有效且仍是同一存档代际／游戏／前台运行边界时，用**已确认的新版本**串行保存一次暂停。蛇的暂停／继续不增加 step，方块则增加；不混用两种协议。
4. 原请求已经携带的转向仍按服务端结果保存，不撤销已接受的一步，继续后也不重放它。
5. 若该步恰好结束棋盘，旧 C 只让画面停住，不发送暂停或收好。必须**重新按 B/C** 才收好成绩；未达到奖励条件也不会补发陪伴或金币。

仅开放这一自动节拍窗口。主动继续、左右移动、旋转、落底及暂停保存本身仍锁定三键；没有通用动作队列，没有新增 LCD 可点击控件。

## 失败、离开与存档

- 步进失败、结果未知、无效回复不补发暂停，也不重放步进。按原恢复流程核对，成功读取不自动继续。
- 暂停保存失败／未知不重试。刷新后本地仍暂停，必须重新明确继续。
- 打开说明／工具、失焦、切后台、卸载、存档替换、游戏变更或服务器已暂停，都会使旧意图失效。晚到的成功回复只保留已经接受的棋盘，不越过中断边界追加写操作。
- 不修改后端、schema17、养成、额度、奖励或旧档迁移。自动暂停不会新增陪伴或共同经历。

## 验证方式与范围

- `web/src/AutomaticBoardPause.test.tsx`：针对两种 step 协议，覆盖机身 C、渲染前间隙、A/B 不排队、连续 C、暂停自身在途、多个终局、代际／局 ID／空局变更、后台／失焦／帮助／卸载、未知／拒绝、主动命令锁定及已发蛇转向不重放。
- `scripts/check-board-pulse-pause.mjs`：独立临时 SQLite、二进制、网页构建与随机端口；实际 HTTP 操作，两种视口各覆盖两款游戏的八种受控回复／中断，以及自然时钟走到终局后暂扣最后一步回复。不存在改玩家数据库、伪造棋盘或加速服务器时间。
- 320px 使用双倍根字号和强制颜色；检查无横向溢出、仅三机身按钮、LCD 无玩法控件、刷新不继续／重放，最后另按 B 才收好一次。
- 脚本在导入浏览器与启动服务前检查隔离路径；缺省、共享或其别名／硬链接构建不能用于测试。使用方式见[隔离构建](DEVELOPMENT.md#验证与隔离构建)。
