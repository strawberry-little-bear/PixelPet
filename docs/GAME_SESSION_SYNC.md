# 同存档内的多页小游戏同步（2026-10-19）

## 本批修复

存档代次保护负责导入/重新开始，但普通游戏开始、完成、放弃不会换存档代次。本批在接受新的权威读取后，另外比较小游戏局 ID，以及四种需要手动收好的游戏是否刚进入终局：

- 另一页开始接星星、连连看、蛇、方块、钓鱼或散步后，本页转入对应游戏，不再留在不可继续照顾的小窝/阅读页。
- 换局后清掉旧放弃确认、暂停菜单选项、导入预览、重新开始/购买确认和说明面板，重新定位星星位置/选牌光标。不会把旧菜单的「放弃」带入新局。
- 蛇/方块结束、钓鱼三竿结束或散步到终点时，即使局 ID 没变，也清掉未完成时打开的放弃确认。显示实际结果，明确按 B / C 收好，不自动领奖。
- 游戏已在另一页移除时回小窝，不重播结算；实时游戏仍需本页明确继续，不因同步自动走格、下落、钓鱼或赶路。
- 同局普通进度/重复终局读取不打断阅读、说明或主动打开的放弃确认；低版本响应先拒绝，不清掉当前操作意图；迟到文件读取不能恢复已丢弃的导入预览。

没有新增玩法按钮、游戏、存档字段、成长/金币数值或后端结算规则。schema 仍是 11，旧存档与成年固定形态沿用原规则。游戏局标识不替代安装级 `save_generation`，反之亦然。

## 明确的剩余边界

本批修复的是**已接受新读取之后**的本地旧意图失效。局 ID 能隔离新旧局，但不能识别同一局在尚未同步时从未完成变成终局；服务端原有 `cancel-play` 仍允许丢弃终局，本批没有悄悄改它的兼容规则。下一批优先验证「旧放弃确认先发出、终局已在另一页产生」这段未同步窗口，考虑可选命令前置条件；失败必须不写入、不自动领奖，继续兼容旧客户端和存档。不能把本批自测宣称为全部多页竞争已消除。
