# 纪念册响应保护（2026-10-19）

## 复现与修复

纪念册对回忆数组执行筛选/排序，并把日期转换为 ISO 字符串。此前核心响应检查未覆盖 `album`，因此 HTTP 成功并不保证显示安全。隔离旧版前端中，已打开纪念册后收到 `entries: {}` 的访问响应，Chrome 报出 `.filter is not a function`，面板被卸载。

现在在接受响应前校验纪念册的显示必需字段：元数据、回忆数组、条目类型/日期/来源，以及可选模样、分数、天数、物品字段。不把异常记录清空为“没有回忆”，也不猜测或修复历史。缺失/null 纪念册及空/null 回忆列表仍可读取，兼容旧服务与 Go 的 nil slice；物品 ID 不绑定当前装扮目录。

异常读取进入现有 B 键只读恢复；异常写回复仍视为结果未知，只读核对存档，不重发动作或伪造成功反馈。时间先后、唯一性、回忆获得条件、迁移与存档业务校验仍由服务端负责。本批不改后端、schema、成长数值或三键规则。

## 验收

- 新增单元/API 49 项、App 真实 fetch 恢复路径 12 项。旧实现其中 38 项失败；修复后专项 128 项通过。
- 全量前端 **2453 项 / 100 文件**、TypeScript、生产构建及 Go 无缓存 race（包串行）/vet/构建通过。
- 新独立库 Chrome **24 组**：1200px 与 320px（双倍根字号、强制颜色），覆盖首次读取/打开纪念册后同步/真实喂食已保存但回复损坏，各有非数组、null 条目、非法日期；另测缺失/null/空旧纪念册。
- 验证异常状态可用 B 恢复，未知写只发一次动作，不丢失真实新增的首次饭团回忆；没有额外金币、游戏写请求或 LCD 玩法控件，没有运行时错误，文字不横向裁切。桌面与小屏截图已查看。

长历史与损坏数据是 HTTP 响应夹具，不是修改玩家存档，也不冒称真实历史。实际临时数据库另行检查：读取场景纪念册不变；喂食场景保留原记录且只新增一条真实 shared meal。

## 重跑与边界

构建前端和测试二进制后，设置绝对路径 `PIXELPET_TEST_BINARY`，必要时设置 `PIXELPET_PLAYWRIGHT_MODULE`，运行：

```sh
node scripts/check-album-response.mjs
```

脚本自建临时数据库、随机端口和 Chrome，结束后关闭自己的服务。`PIXELPET_TEST_WEB` 可指定隔离旧版前端以复现，不接收玩家 URL/数据库。它不等同于全 schema 审计、所有浏览器认证或真人触屏/读屏验收。玩家库和原服务保持不变。

补充复跑结果：既有节奏算术 6 项、回访布局 12 组、原生滚动中途换页 96 次、成长/照顾/回访响应 64 组及共同游戏响应 22 组全部通过；未放宽等高、滚到底或归零断言。
