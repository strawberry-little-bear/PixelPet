# 存档代次：旧页面不能误写替换后的存档

## 问题与实现（2026-10-19）

两页同时打开时，旧页下一次轮询之前仍能操作。即使另一页导入的是同一只宠物，创建时间、孵化时间、物种都没有变化，旧页已打开的喂食、重开、导入或游戏确认也不应执行到替换后的存档上。先新增 HTTP 回归，五条旧操作在修改前全部错误返回 200，随后实现保护。

- SQLite 单独保存安装内 `save_generation`，初次打开旧库时补充，不重写宠物原始存档。使用密码学随机的 32 位十六进制标记，服务重启不变。
- **成功导入或重新开始**才轮换代次，即使恢复的是完全相同的备份。轮换、快照、替换、清请求缓存及回访数据在同一事务内；失败整体回滚。普通照顾、时间结算、孵化、读取和缓存回复不轮换。
- 更新后的页面将最近接受的 `saveGeneration` 放入 `X-PixelPet-Generation`，覆盖动作、导入、重新开始和回访已读四种写入入口。服务端在事务内、查幂等缓存和推进时间之前核对，不匹配返回 HTTP 409 / `save_changed`；不留下照顾、奖励、快照、会话超时或访问记录副作用。
- 读取和访问仍能取得当前代次，不因旧代次阻止重新同步。坏档诊断也返回安装代次，让首次打开坏档后的明确修复受保护；另一代坏档出现时，不把先前的修复预览自动绑定过去。
- 页面明确提示「**本次操作未执行**」，清理旧确认和待导入文件，停止动画与自动运行；不会重发被拒绝操作。B 只读取当前存档，再次照顾或替换需要新的主动操作。读取失败或读到较旧响应时仍保留“已拒绝”的准确说明，不混淆为“可能已保存”。正常轮询也能发现同身份备份的新代次并退出旧面板。
- revision 只在同一代次内比较。明确修复坏档可能将不可读的 revision 恢复为较小值；仅新鲜、通过本地请求代次校验的权威读取能跨此边界，旧响应不能覆盖新确认。

## 兼容和范围

- 宠物 schema **仍为 11**，JSON 备份仍是宠物状态，不携带安装代次；旧备份和成年固定形态不变。不改成长、需求衰减、每日奖励或六款游戏规则。
- 为兼容旧客户端，**未提供请求头仍可操作，也不享受这项保护**。多页安全使用需要更新后的客户端配合同版本服务端。这不是身份认证、跨设备同步或阻止手动替换整个 SQLite 文件的机制。
- 保留既有 15 秒轮询/可见性读取，没有新增实时推送。不解决同一代内全部多页照顾竞争：仍以服务端动作校验与幂等规则为准。
- 玩法保持 A/B/C，LCD 不新增点击控件。存档盒仍是原有的文件管理入口。
