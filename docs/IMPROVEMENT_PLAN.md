# 非小游戏完善计划（2026-10-19）

状态：计划已制定，以下批次尚未实现或验收。本轮转向可靠性、照顾理解和日常陪伴，不等待小游戏试玩反馈才开始，也不把已有功能重新算成新增交付。

## 现有基础与本轮边界

已有六款小游戏、十只角色的独立三阶段造型、离线状态结算、成长手册、回访小结、日记、永久纪念、有限游戏兴趣、商城布置和 JSON 备份导入导出。现有错误提示、忙碌保护与部分恢复测试也已存在；下面是补强与专项核查，不代表这些能力全部缺失。

本轮暂不新增小游戏、角色、货币、登录、云存档或社交；不修改成长阈值、状态衰减速度、成年形态锁定和每日奖励规则。节奏拍手与森林寻宝保留候选，不能算成已实现。

## 第一批 P0：保存与连接状态可信

**目的：让玩家区分「正在保存」「连接异常」和「结果尚未确认」，不把网络异常误报为一定没保存。**

- 先核查请求层与现有 App 状态，只补真实缺口，不一次重构六个游戏。
- 区分确定被拒绝的操作与断网/超时造成的未知结果；只有收到服务端确认才播放成功动作或展示成功结算。
- 对请求已到服务端但响应丢失的情况，恢复连接后读取权威状态；不自动重放喂食、购买、领奖等写操作，也不承诺所有操作都能推断出原请求结果。
- 未确认期间避免继续提交相冲突操作，使用现有 A/B/C 交互恢复；读取失败仍保留可解释的连接状态，不静默当作同步成功。
- 小游戏保持现有手动续局/暂停边界，恢复连接不能自动续跑或弹出成功领奖。

**验收：**独立数据库覆盖请求发送前失败、服务端保存后响应丢失、恢复读取失败/成功、连续按键、旧响应晚到和刷新。至少实测一条照顾链路与一条购买/结算链路，确认不重复扣款、不凭失败响应撤销已保存结果、不伪造成功动画。只有现有实现或新测试证明的项目才记为已完成。

## 第二批 P1：照顾与成长更容易理解

**目的：不改变养成数值，让玩家知道宠物为何变化、现在适合做什么。**

- 在现有状态页、成长手册和照顾反馈中补足解释，不另建一套任务系统。
- 区分有效照顾、需求已经满足、动作暂不可用；反馈依据服务端真实结果，不承诺每次按键都增加成长。
- 清楚说明离线状态/成长结算最多 12 小时、睡眠恢复与现实相识天数的区别；长时间不在不加入死亡、断签或补做任务惩罚。
- 成年说明强调形态已固定，后续仍能留下共同经历；不暗示继续喂食可以反复刷成年形态。
- 优先调整文案与已有展示，确需新增数据时先审字段来源和旧档默认行为。

**验收：**幼年/成长/成年 × 清醒/睡眠；有效照顾、需求已满足、失败请求与旧档案例。前后端结果一致、解释不越过现有规则，手机说明不裁切，三键操作不变。

## 第三批 P1：三键可达性与阅读专项

**目的：从「手机不整体缩放」继续做到文字可读、焦点明确、不会误触退出。**

- 专项检查 320/390px、短屏滚动、200% 文本放大、高对比度与减少动态效果。
- 检查键盘与触摸切换、按键重复事件、菜单返回路径、弹层开关后的焦点；与 P0 已有忙碌保护共用，不另造按键系统。
- 仅修验证出来的布局与导航问题；屏幕内仍不新增可点击玩法控件，不擅改六款游戏的速度或难度。
- 长文字允许合理分页/滚动，不能为了塞进屏幕而删掉关键规则或阻断 A/B/C。

**验收：**小窝、状态、成长手册、商店、纪念册及暂停页可读可返回；键盘单次操作不被重复执行，触摸后关键内容与三键均可到达。记录实际截图与人工操作路径，不以仅无横向溢出替代可用性验收。

## 第四批 P2：成年后的回忆更好找

**目的：用已有真实经历增强陪伴，不堆计数或制造每日负担。**

- 先核查永久纪念册、日记和兴趣页的入口及返回路径，再选择一个小范围改进。
- 候选为纪念册三键分类浏览：A 切分类、B 进入并沿用翻页、C 返回；明确无记录状态，保留所有旧卡片及其来源说明。具体键义需先验证与现有翻页不冲突。
- 不增加亲密度货币、连续登录目标、强制指定游戏；不倒填旧存档不存在的故事，不把同一次经历重复记录。
- 本批不同时扩展新纪念事件、纪念搜索和复杂养成分支。

**验收：**空册、少量与完整卡片、旧档迁移来源、刷新/重启后记录一致；全部能用三键找到并返回，成年形态不变。

## 交付节奏

1. 一次只实施一批；第一批从请求状态审计和可重复的失败测试开始，不以缺少试玩反馈为阻塞。
2. 各批针对性测试 → 前端回归/类型检查/构建 → Go 测试（含竞态）、vet/构建；涉及界面时另做独立数据库的真实浏览器验收。纯计划文档不冒称通过新增功能测试。
3. 不重置、导入覆盖或代操作 `data/pixelpet.db`；浏览器验收明确指定临时数据库与独立端口。
4. 保持旧档兼容。每批验收通过后，以草莓小熊为 author 和 committer 提交并推送 GitHub；提交前后核对身份，不重写历史。
5. 汇报明确区分计划、已实现、已验证、已推送及未完成部分。若审计发现能力已完整，不为凑功能而重复实现，报告证据后进入下一批。
