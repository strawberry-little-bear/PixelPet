# 一起玩过的小纪念物

七款小游戏各留一件小纪念物，放在「纪念册 → 一起玩过」。这是已经发生过的共同游戏留下的记号，不需要集齐，没有每日任务或断签要求。

## 怎样留下纪念物

升级到支持纪念物的版本后，每款游戏第一次符合原有共同游戏条件的结算会留一件。旧版已经玩过的游戏，需要再完成一次符合条件的结算；不会补写过去，也不声称这是玩家第一次玩。

| 游戏 | 纪念物 | 沿用的结算条件 |
| --- | --- | --- |
| 接星星 | 小缎带 | 完成五轮，分数不限 |
| 连连看 | 小篮子 | 连好八对图案 |
| 贪吃蛇 | 果园叶子 | 吃到至少三颗果子后收好成绩 |
| 俄罗斯方块 | 小方块 | 消除至少两行后收好成绩 |
| 钓鱼 | 池塘贝壳 | 三竿结束，至少钓获一条鱼，再收好成绩 |
| 公园散步 | 路上纽扣 | 走完整条路线，再收好经历 |
| 森林寻宝 | 林间木牌 | 完成一次合法探索，再收好发现，不要求找齐 |

- 每种只留一件，重玩不会改写物品或日期。
- 不增加金币、成长、兴趣或状态奖励，原有结算规则照常执行。
- 金币每日额度耗尽或钱包已满，仍可按上述条件留下纪念物。
- 准备、暂停、放弃、未达条件或离线经过时间都不会发放。

## 看见和翻阅

本页收到有效结算、确认新物品已保存后，会提示可以到「纪念册 → 一起玩过」查看。刷新页面不会重放这条提示，纪念物仍保存在存档中。

纪念物各有独立图案和文字，A 上一页、B 下一页、C 返回分类。页面同步以具体物品定位，不会把七件物品当作同一页；同步后选中的物品已不存在时，回到本类封面。LCD 内没有新增点击控件。

## 存档边界

存档版本为 schema 21，新增 `kind: "keepsake"` 的永久回忆，以 `item` 区分七件物品。沿用 `source: "shared"` 和真实结算时间；普通游戏纪念卡继续保留，游戏种类和完成局数也不从纪念物数量推算。

schema 20 升级只提高版本，不补造物品、不重置当前游戏。现有存档迁移快照机制保留迁移前的数据。低版本不接受新回忆类型；新版校验物品、来源、重复、时间以及对应游戏卡和完成记录。导出和导入保留物品及日期。

## 回归验证

- `internal/game/keepsake_test.go`：七款游戏、额度、重复、放弃、不合格结算、旧档迁移、非法记录及 JSON 往返。
- `internal/store/keepsake_test.go`：临时 SQLite 中迁移只留一份快照，进行中的游戏不变，结算重试和导入不丢失或复制物品。
- `web/src/GameKeepsake.test.tsx`：七种图案和文案、同时间多物品独立翻阅及同步定位、无历史不补造、新获得提示的边界。
- `scripts/check-game-keepsakes.mjs`：独立服务与数据库中实际完成两局接星星，验证提示、重复、刷新、备份往返，以及桌面、320px 和双倍字号阅读。

浏览器脚本要求提供绝对路径的 `PIXELPET_TEST_BINARY`、`PIXELPET_TEST_WEB`，构建产物必须在共享 `bin/` 和 `web/dist/` 之外；可通过 `PIXELPET_PLAYWRIGHT_MODULE` 指定 Playwright 模块。不连接正在游玩的服务。

本轮前端全量命令为 `pnpm exec vitest run --testTimeout=30000 --maxWorkers=2`。首次默认并发运行出现超时后中止；降低并发重跑，214 个文件 / 5634 项全部通过。浏览器专项四组通过，包括真实游玩／备份往返和三种视口字号组合。
