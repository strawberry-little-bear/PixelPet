# 回访小结开头的外层视口定位（2026-10-20）

## 复现

固定 LCD 内部高度与翻页归零不能解决外层文档位置：320px × 380px、根字号28px（正常14px的200%）下，通过机身 B 从菜单打开回访小结，页头 y=-222.2px；B 继续第二页仍是 y=-222.2px。眼前是内容尾部和三键，玩家需要先把整个网页滚回去，才知道小结从哪里读。独立Chrome截图和日志在`/tmp/pet-return-viewport/before-open.png`、`before-page2.png`、`red.log`。新的浏览器回归也在旧构建的桌面菜单重看路径复现标题y=-76px。

## 改动边界

- 菜单重看、A换页、第一页B继续，以及原有认领流程真正展示小结时，生成一次定位意图；页头未完整出现在视口才立即滚动外层文档到约12px留白。
- 同一记录轮询、最新记录替换、帮助关闭、回到前台、异常恢复不生成定位。换记录仍按原逻辑回第一页、内部归零和提示更新；不因此额外滚动外层网页。B最后一页/C返回不定位。
- 复用`useReadingViewport`，以存档generation/宠物生命周期、记录ID和目标页校验；后台、覆盖层或不匹配上下文丢弃意图，不等恢复后补跳。
- 不改变焦点、原生键盘/触摸滚动、固定LCD高度、sticky页头、面板换页重建及原生End动画中断机制。不加LCD玩法控件；仍只有A/B/C。
- 不改认领时机、睡眠/成长/奖励/schema或旧档迁移；无新的网络写请求。首次自动展示仍须原有服务端认领成功，睡眠不自动认领。既有`check-return-layout.mjs`补充独立构建路径参数，避免回归只能读取共享dist。

## 复跑

```sh
./.tools/go/bin/go build -o /tmp/pixelpet-return-viewport ./cmd/pet
# TypeScript及Vite需先输出到独立构建目录，不覆盖共享web/dist。
PIXELPET_TEST_BINARY=/tmp/pixelpet-return-viewport \
PIXELPET_TEST_WEB=/absolute/path/to/isolated/web \
PIXELPET_PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs \
node scripts/check-return-viewport.mjs
```

到访基线设置使用Python标准库sqlite3，默认`/usr/bin/python3`；其他环境通过`PIXELPET_PYTHON`指定可用解释器。脚本只接受自己生成的临时数据库，不接受玩家数据库或URL。全页截图仅作诊断，先核对原生可见标题、同步不跳与内部末尾可读，再拍全页图，不用截图后的移动补救失败。
