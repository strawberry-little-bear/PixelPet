# 空图鉴兼容与响应保护（2026-10-20）

## 问题边界

Go 的 `validPond` / `validPark` 允许合法的空 nil 切片。已有对象的 `fish` / `finds` 为 `null`，或保存的 JSON 省略集合字段，读取时都可能得到 `null`。原前端的 `pond?.fish.find` 只保护外层对象；进入鱼图鉴或沿途发现时仍会抛出 TypeError。发现计数、鱼影遮罩和钓获说明中同类访问也一并补齐集合的可选链。

**不把这个问题描述成正常导入必然白屏**：当前导入已通过防御性拷贝把 nil 集合转为 `[]`，新建存档也使用 `[]`。本轮针对的是服务端校验允许、持久化读取确实可返回的空集合表示；不声称在用户正在玩的存档中发现了此问题。

## 修复

- 类型明确允许集合字段缺失或为 null；读取按零发现、未遇见显示，不改写状态或补造发现日期。
- API 在接受成功回复前检查可选 `pond` / `park` 的显示安全结构：集合必须为缺失/null/数组；非空记录需要已知 ID、可显示日期和正整数次数。元数据也必须有安全类型。
- 不用 `Array.isArray ? value : []` 把坏记录藏成空历史。畸形对象、字符串集合、null 条目、不安全日期和次数走原有恢复机制。
- 异常初次读取/同步可按 B 只读恢复；异常写回复仍是“结果未知”，不重发喂食，不补播成功/进化反馈，也不能据此断言数据库损坏。
- 这不是第二套存档校验器；时间顺序、重复 ID、发现资格和计数业务上限仍由服务端校验。不改 schema17、导入拷贝、成长、概率、奖励或离线规则；仍只有 A/B/C。
