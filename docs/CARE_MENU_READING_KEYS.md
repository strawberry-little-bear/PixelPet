# 照顾菜单的原生键盘阅读（2026-10-20）

## 行为与边界

照顾菜单现在沿用成长手册／状态页的 `CareReadingRegion`，将选项、最近读取的照顾建议、操作预览和休息进度放在一个可 Tab 到达的命名只读区中。旧版已有自然文档滚动；这次是阅读增强，不声称此前完全不能键盘滚动，也没有复现正常游玩中误喂食／误叫醒的产品 Bug。

- Tab 可进入、离开「照顾菜单阅读区」，不自动聚焦、不陷焦点，不增加按钮或 LCD 可点击玩法控件。
- 聚焦后 ↑/↓、空格、Shift+空格、PageUp/PageDown、Home/End 保留浏览器默认文档滚动；长按也不选择或执行照顾。
- **仅在这个菜单阅读区内，Enter 不确认照顾**，提示明确写出。显式 A 选择、B 确认、C／Escape 返回不变。
- 焦点在机身 A/B/C 按钮时，Enter／空格仍只执行一次该物理键的操作。成长／状态页默认提示和其他页面的 Enter 协议不变。
- 使用既有 2px 内侧焦点轮廓和强制颜色支持。没有新固定高度、内部滚动或 CSS 布局策略；长预览自然撑开，明确选项切换仍定位当前行。
- 普通同步保留阅读节点、焦点、选项和文档滚动位置；仅阅读不执行喂食、清洁或叫醒。

不改后端、schema、离线结算、成长、奖励或存档格式，不从浏览器时间推进需求。

## 验证与复跑

新增 `CareMenuReadingKeyboard.test.tsx` 11项：清醒／睡眠的命名停靠点、无抢焦点／可点击控件、原生／长按／Shift阅读键、Enter、显式三键、返回、普通同步以及物理 A/B 的原生激活。最终测试文件在旧源码上 **8失败／3通过**，新实现全量 **4159项／153文件** 通过；TypeScript、独立 Vite 构建、Go无缓存全量 race／vet／独立构建通过。Vite仍有既有主包超过500kB的体积提示。

`check-care-menu-keyboard.mjs` 在自己的随机端口、临时 SQLite 和浏览器运行 **18组**：三阶段 × 清醒／睡眠 × 桌面1200×700／320×700／320×380。手机根字号28px（正常14px的200%），同时启用强制颜色；验证实际正文字号翻倍。

每组真实 Shift+Tab 从机身 A 到达阅读区，检查命名、关联提示、可见轮廓、只有三键；用七种真实原生键滚动（共126次）、重复空格／方向键／Enter，逐行检查长说明和休息进度可读、无横向溢出；普通同步不跳滚动／焦点且无照顾写请求；最后 Tab 到机身 B，用 Enter 或空格**明确执行一次**真实喂食／起床。截图分阅读聚焦、阅读底部和最终明确操作后，不用操作后页面冒充阅读截图。

原生按键测试给各方向留出滚动空间；重复键后等待浏览器滚动动画稳定，再测同步不跳，不把尚未结束的默认滚动误报成同步定位故障。旧独立构建的浏览器红测因不存在命名阅读区而失败，只证明增强缺失。

阶段由schema1年龄迁移夹具产生，睡眠由真实HTTP `sleep` 操作开始；不是自然多日养成。读取允许正常服务端时间结算，不声称读取完全不写数据库。交叉回归：既有照顾菜单定位15组、成长／状态阅读18组、物理键盘48组。
