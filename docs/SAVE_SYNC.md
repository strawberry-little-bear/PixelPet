# 多页面同步：伙伴变了，旧画面也要退出

## 本批修复（2026-10-19）

此前轮询能更新宠物数据，却只在首次加载或连接恢复时选择画面。因此另一页孵化后，本页仍可能停在选蛋/孵化确认；另一页重新开始后，本页仍可能留在旧伙伴的菜单、成长手册或游戏中。

- 记录最近一次接受的状态。新鲜读取中，创建时间、孵化时间或已孵化物种改变，说明原导航已不适用：转到选蛋、小窝或当前已保存的游戏。
- 同时清除旧动画、照顾反馈、说明/存档盒/重新开始确认、待导入文件、购买/放弃确认和本地自动运行许可。读取中的旧文件即使随后完成，也不能重新打开预览。
- 不重放孵化、照顾或游戏操作；接受新棋盘不代表自动继续。不同伙伴的成年阶段不伪装成本页刚发生的进化。
- 新鲜读取明确没有回访记录时，清掉缓存记录；若正在看该记录则返回小窝，避免残留旧内容或空白页。同一伙伴的备份导入也会清掉安装内回访记录。
- 普通需求衰减、同一伙伴成长不强制离开手册或重置选蛋选择；真实成长仍保留原有庆祝。较旧 revision 不能清除当前导航、确认或回访记录。

## 边界

这不是新增的存档代次协议：同一只宠物的备份可保留创建/孵化时间和物种，本批不声称能识别其全部导入意图。回访数据以新鲜响应为准；其余保持现有服务端校验。没有实时推送或跨设备云同步，沿用 15 秒轮询和回前台读取；同步前的跨页并发写入仍按原服务端规则处理。

只用 A/B/C 玩法键，不增 LCD 点击控件、不改数值、奖励、成年定型或 schema（仍为 11）。

后续已增加安装级事务保护，解决更新客户端在同身份导入后旧意图误写的问题；旧客户端无请求头不受保护。详见 [SAVE_GENERATION.md](SAVE_GENERATION.md)。下述数字仍为本批历史验证，不重复计入后续批次。
