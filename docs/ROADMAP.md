# 长期陪伴路线

先把本地玩法做好，部署、账号和云存档不是当前优先项。完整目标不是若干独立小游戏的合集，而是「照顾与陪伴 → 宠物参加游戏 → 获得金币 → 购买装扮 → 回小窝展示与留下记忆」。全程保持 A / B / C 三键。

## 1. 回访与主动表达

- [x] 回访小结：真实状态、有效休息、成长与跨阶段变化；无额外奖励。
- [x] 前台访问与后台读取分离；离开至少 15 分钟形成一次小结。
- [x] 服务端保存最近小结及消费状态；刷新不重复自动播报，多标签页只认领一次。
- [x] 睡眠、小游戏、照顾与进化动画期间延后；菜单可主动重看最近小结。
- [ ] 主动需求：确定性规则选择饥饿、疲惫、想玩、满足；紧急需求优先，睡眠与动作优先于需求。
- [ ] 需求配合表情与轻动作，刚吃饱不再喊饿，睡眠时不邀玩。

## 2. 成年后的陪伴

- [ ] 最近 30 条日记以外的永久纪念册：首次成长/成年、陪伴天数、共同经历。
- [ ] 以情感记忆和关系感为主，不仅堆计数；成年形态保持锁定。
- [ ] 旧存档不编造未记录的历史，能证实的成长时间可以沿用。

## 3. 真正的角色与阶段差异

- [ ] 先做一只完整样板：幼年、成长、成年有独立造型/动作，而不是原图缩放、全身摇晃加配饰。
- [ ] 样板验收后推广到十只，补各自习惯、阶段肢体动作和成年形态表现。
- [ ] 保留原始角色辨识度、统一像素风格，照顾和需求都要有可见反馈。

## 4. 金币、商城、装扮与宠物小游戏

- [ ] 持久化金币、物品目录、库存、购买与穿戴，小窝及游戏里展示装扮。
- [ ] 日常签到：少量金币、一天一次，不设断签惩罚。
- [ ] 完整小游戏结算后获得金币；服务端校验会话与成绩，幂等结算，取消不刷币。
- [ ] 宠物参与连连看、贪吃蛇、俄罗斯方块等玩法，先设计三键控制，再逐项实现与验证。
- [ ] 将共同游戏、装扮与长期纪念连接起来，避免只有孤立的分数与商店。

## 每批验收

旧存档兼容；不新增玩法按钮；不打断睡眠/游戏/进化；竞态测试、前端测试、类型检查与构建；独立数据库的桌面/手机实际浏览器验证；不覆盖玩家存档。测试通过后，以草莓小熊为作者和提交者提交，不擅自推送。
