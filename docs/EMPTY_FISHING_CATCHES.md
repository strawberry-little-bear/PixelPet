# 合法空渔获的钓鱼恢复（2026-10-20）

## 可复现边界

`validFishingGame` 允许没有钓到鱼时 `Catches` 为 nil。JSON 的 `catches: null` 或省略字段都能解码成此状态；准备、等待、咬钩、提前收竿后的结果、三竿结束均有合法实例。SQLite 正常读取/重开不会替它补造数组或渔获。旧前端直接读取 `n.catches.length`，即使是合法状态也会白屏。

新建游戏本来使用 `[]`，备份导入本来也会结束进行中的游戏；**不声称正常新开局/导入必然触发，更不声称玩家当前存档有此问题**。本批只修复经过服务端校验、实际持久化读取可返回的兼容边界。

## 修改与边界

- `Fishing.catches` 类型明确允许 null/缺失。计数、结束说明和奖励资格提示共用 `catches?.length ?? 0`，不改写已接受状态，不造鱼、不重抽候选、不自动续局。
- API 接受回复前，只检查钓鱼模型及渔获的显示安全结构：null/缺失为合法空集合，提供的数组最多三项且均是已知鱼种；不存在的钓鱼模型、对象/字符串集合、null/未知条目不隐藏成零条鱼。
- 这不是完整的钓鱼存档校验器：阶段、抛竿次数、等待、虚构雨景资格、发现证据和奖励仍由服务端负责。无后端产品逻辑、schema17、概率、成长、照顾或离线规则改动。
- 初次/定时读取的坏回复仍可按 B 只读恢复；写回复异常仍为“可能已经保存”，只核对、不自动重发，也不补播成功/进化反馈。不据此断言数据库损坏。
- 仍只有 A/B/C；三竿零渔获可正常收好但无金币/陪伴计数，真实首次钓获只记录一次；完成三竿且仅一鱼仍按原规则结算三币。
