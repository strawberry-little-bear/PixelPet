# 纪念册同步时的阅读定位 · 2026-10-19

## 问题与交付

原来纪念册只保存页码。回忆按时间与种类排序，收到排在前面的新回忆时，同一个页码可能显示另一条内容。新增应用回归先在旧实现失败：正在看的 `meal` 被同毫秒的 `bath` 替换。Go 回归确认同一时间先喂食再洗澡可以产生合法、不同种类但相同时间戳的回忆；时间戳不能充当唯一身份。

- 改用存档既有的回忆身份定位：通常按 `kind`，相识日里程碑按 `kind + days`。不增加永久 ID 或修改 schema。
- 收到新记录/排序变化，仍看原来那条；页码反映最新排序。A / B 从现在的位置继续翻页，末页回到本类封面。
- 每次渲染读取最新存档内容，不把前端保存的旧文案/日期/分数当成权威记录。旧迁移、真实共同经历、相识日期的来源说明保持不变，不倒填当时照顾或外观。
- 封面、分类目录不自动追踪新回忆；C 返回分类，再进入时从封面开始。回到小窝后重新打开仍从分类目录开始。
- 防御性处理同步后选中回忆不存在：立即返回本类封面并说明，不显示幽灵旧记录，也不悄悄切换到相邻条目。普通轮询保留说明，下一次明确翻页/重新进入清除；记录随后重现也不自动跳回。永久纪念册不会自然按 30 条淘汰，此路径不是日记滚动淘汰。
- 换存档/新局沿用已有安全同步流程，回小窝后重新打开不继承旧锚点。旧服务缺少 album 或合法空分类仍可只读浏览，无虚构日期、记录或奖励。

没有新增屏幕内玩法按钮，仍只有 A / B / C。没有更改成长、需求速率、成年形态、金币、回忆条件、离线结算或旧备份。浏览不发照顾、认领奖励、导入或重置请求。
