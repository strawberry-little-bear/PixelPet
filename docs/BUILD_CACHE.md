# 稳定运行时分包与更新缓存

[文档导航](README.md) · [开发与隔离构建](DEVELOPMENT.md)

## 做了什么

- React、React DOM、scheduler 提取为独立 `react-vendor` 内容哈希包；仍是立即导入并预加载的依赖，不延迟小游戏、不增加加载确认或玩法控件。
- 游戏代码更新但依赖不变时，运行时的文件名和实际字节保持一致，浏览器可复用缓存。
- Go 静态服务只对 `/assets/名称-八位哈希.js`／`.css` 的 200、206、304 回复设置 `public, max-age=31536000, immutable`。这些路径必须保留构建产生的内容，不允许手工同名覆盖。
- HTML 和目录入口使用 `no-store`；其他公共文件使用 `no-cache`。哈希资源的错误或重定向不带长期缓存，避免缓存缺失文件的错误响应。
- API 状态与备份仍为 `no-store`，不把玩家存档交给浏览器缓存。三键、schema17、养成和奖励规则不变。

## 为什么入口页不只用 no-cache

独立 Chrome 验证复现：替换构建但保留 HTML 的秒级修改时间时，`no-cache` 重新校验后仍加载旧入口，新增的游戏标记没有出现。Chrome 文档事件给出有效状态200，不把它当作线上原始304的证据；Go 的独立条件请求测试另证实相同 `If-Modified-Since` 会返回304，单靠秒级修改时间无法区分该更新。改为 `no-store` 后，同样的时间戳下正常获取新 HTML、加载新游戏包，并从浏览器缓存取得未变化的运行时。

这不修复已经由旧版本缓存的文档，也不实现在线热更新；更新后需正常重新打开或刷新。没有 Service Worker、离线安装或原子部署机制。请停止测试服务后再替换构建；不要把本测试的临时目录复制操作当作生产部署脚本。已打开旧页面时删除其引用的旧文件，仍可能造成后续请求失败。

## 包体边界

本批隔离旧构建主 JS 为 **505.11 kB**；拆分后的实际构建约 **280.93 kB 游戏包 + 223.21 kB 运行时**，每个 JS 均低于既有 500 kB 警告阈值，没有提高或关闭阈值。

**这不是首次总下载量下降的承诺。** 首次仍需下载两包，压缩总量可能略增；优化的是稳定依赖跨游戏更新复用。缓存命中由浏览器、缓存保留情况与服务配置共同决定，不代表所有场景都不会再请求。

## 验证方法

### 临时双构建（CI 包含）

```sh
node scripts/check-build-cache.mjs
```

脚本只复制源码到系统临时目录并复用已安装依赖，不写仓库 `web/dist`。第一次构建后，只在临时源码追加可观察的标记，再构建；检查：

1. 主包、独立运行时与 HTML 模块预加载关系正常。
2. manifest 的资源、依赖、CSS 均可读取，运行时不反向依赖游戏代码。
3. 每个 JS 保持原 500 kB 限制，构建没有大包警告。
4. 游戏包哈希改变，运行时文件名和字节都不变。

结果 JSON、两次构建与日志保留在输出的临时目录。

### 真实 Chrome 缓存与三键保存（本地专项）

先按开发说明生成独立 Go 二进制，再使用上述脚本输出的 `before`／`after` 目录：

```sh
PIXELPET_TEST_BINARY="/绝对路径/独立/pixelpet" \
PIXELPET_TEST_WEB="/绝对路径/临时双构建/before" \
PIXELPET_CACHE_NEXT_WEB="/绝对路径/临时双构建/after" \
PIXELPET_PLAYWRIGHT_MODULE="/绝对路径/playwright/index.mjs" \
node scripts/check-runtime-cache.mjs
```

先校验两份输入构建均不指向共享 dist；之后复制到第三个临时目录，用新临时 SQLite 和随机本地端口启动独立服务。1200px／320px 两组验证：

- 冷启动实际获取运行时。
- 保持 HTML 修改时间不变，重新打开后读取新版入口与游戏标记。
- 用 Chrome DevTools 网络事件确认运行时命中浏览器缓存，新主包实际获取；无响应拦截或模拟网络缓存。
- 没有页面／控制台错误、请求失败或 HTTP 错误；原三键与无横向溢出保持。
- 更新后通过 A/B/C 完成一次真实喂食保存，服务端照顾次数恰好加一。

Go `TestStaticCachePolicy` 另外通过真实临时 HTTP 服务验证 GET、HEAD、304、Range、412、416、缺失资源、目录重定向、公共图片以及 API／备份的缓存边界。Node 保护测试验证新浏览器脚本在缺少、相对或共享构建时提前拒绝，并始终用自己的临时服务和数据库。

这些检查不是首次下载测速、跨浏览器保证、实体手机或自然多日验收；不访问或更新玩家18102服务与存档。
