# 金币、小窝商店与装扮

## 三键交互

菜单的第 10 项「小窝商店」先显示 **今日问候 / 全部物品 / 宠物装扮 / 小窝摆件 / 墙纸 / 地板 / 已拥有** 七项。A 循环分类，B 领取问候或进入分类，C 回小窝。

进入分类后 A 浏览下一件，B 操作，C 回到原分类（再按 C 回小窝）。未拥有的物品直接显示与当前布置合成的实景预览；预览免费且不写存档。B 打开购买确认，再按 B 扣币购买；A/C 在原物品取消。购买不自动使用，之后 B 使用或收起；已拥有筛选包含全部库存，不因收起而消失。空分类明确提示，不把 B 误当问候或购买。

预览图下方区分「仅预览 · 未购买」「仅预览 · 未使用」「使用中 · 已保存」，只根据服务端已确认的钱包／装备显示，不在请求等待中提前标记成功。收起后仍可免费预览这件物品，但会回到「未使用」；C 回分类时显示真实保存的小窝布置。说明文字可被辅助技术读取，只有装饰画面隐藏，不另加朗读通知或操作控件。

LCD 只有信息与选择光标，没有新增可点击玩法控件；操作仍全部来自 A/B/C。

睡眠中可以只读浏览，不唤醒、不领取、不购买和换装。小游戏期间先完成或 C 退出再进商店；商店期间回访与进化延后到回小窝，不抢断阅读。没有目录或钱包的旧服务会提示更新，不生成假钱包。

## 金币来源与限制

- 每日问候手动领取 10 金币，每服务端 UTC 日一次（北京时间 8 点更新）。只校验日界，不设连续天数、补签、错过惩罚；没有被动或离线金币。
- 现有接星星完整五轮后，奖励 `3 + 服务端命中数`，即 3–8 金币；零分也奖励一起玩完。中途不发币，取消不发币。
- 连连看完整消除八对奖励 6 金币；部分消除、清除选择、取消和自动重排均不发币。
- 所有当前小游戏收入每日上限 30 金币，到上限仍可陪玩、记录真实经历，只是不再发币。跨日自动开始新额度，不积攒未用额度；接近上限按剩余额度发放。
- 钱包上限 1,000,000 金币；游戏奖励按剩余容量截断，问候必须整份放得下，超过容量则拒绝并保留当天领取资格。商店会先说明「钱包放不下本次问候」，B 不发送已知无效的领取请求；余额变化后重新计算，仍需明确 B 领取，不自动领取、不强制购买。旧服务未提供钱包上限时不猜测，实际领取仍由后端判断。后端时间回退不会重领前一天奖励。
- 贪吃蛇吃到至少三颗后结束并手动收好成绩，奖励 `min(果子数, 6)` 金币；少于三颗、主动放弃或仍在进行不结算。七款正式游戏共用每日额度。
- 俄罗斯方块消除至少 2 行、结束后手动收好成绩，奖励 `min(消行数, 6)` 金币；中途放弃、仍在进行、刷新和重试不结算，沿用同一钱包与成长间隔。

- 池塘钓鱼三竿完成且至少一条鱼后手动收好，奖励 `max(3, 2 × 钓到数)`（3–6 币），共享同一额度、钱包和成长间隔。实际钓获即时记入鱼图鉴，放弃保留图鉴但不发币。详见 `FISHING.md`。

- 公园散步实际走完 72 步并收好，奖励 `3 + floor(避开数 / 4)`（3–6 币），沿用共享额度、钱包和成长间隔。第 24/48/72 步发现即时保存，放弃保留发现但无完成奖励；绊到无额外状态惩罚。见 `WALK.md`。

森林寻宝探索六次或找齐三件后，明确 B/C 收好获得 `3 + 实际找到件数`（3–6 币），共享同一额度与钱包；终局揭示的未探索物品不算找到。见[森林寻宝](TREASURE_RULES.md)。

问候容量边界的隔离浏览器回归：[`check-shop-greeting.mjs`](../scripts/check-shop-greeting.mjs)。构造临界钱包后，核对拒绝不消耗领取资格、提示／B 一致、真实购买后可手动领取及刷新不重复；不代表自然积攒到钱包上限。

## 服务端与存档

当前存档版本为 **schema 18**，以[后端 `Schema` 常量](../internal/game/game.go)为准。下列 schema 4–11 条目说明经济相关字段的历史引入，不是当前版本上限；本轮问候提示不新增字段或更改迁移。

- schema 4 增加 `economy`：余额、最后问候时间、最后游戏收益时间、当日游戏收入、库存、装备。前端只发物品 ID，目录/价格/收入/日界由后端决定；额外客户端币价和分数字段被 HTTP 严格解析拒绝。
- schema 5 增加连连看会话和纪念；schema 6 增加贪吃蛇；schema 7 增加俄罗斯方块，schema 8 增加钓鱼与真实鱼图鉴。schema 9 增加独立 `equipped.wallpaper` / `equipped.floor` 槽和两类真实布置纪念。schema 8 升级只更新版本，新槽为空，不改变旧装备、成长、鱼图鉴、进行中的游戏或纪念；不按已有物品补造使用经历。升级保留钱包、库存、成长、纪念和进行中的旧游戏，不补发金币。
- schema 10 增加有限游戏兴趣记录；schema 11 增加公园发现与第六种兴趣，兼容 1–10，保留原五种兴趣；兴趣与收益独立，额度满或钱包满仍记住真实完成，但不多发金币、不增加额外成长。见 `COMPANION.md`。
- 存档 schema 1/2/3 兼容：先执行原成长/纪念迁移，再创建零金币空库存；不补发或编造过去的奖励和物品。保留迁移前快照，兼容旧局并为它生成新的会话 ID。
- 游戏会话由服务端生成独立随机 ID；接星、连连看、贪吃蛇、俄罗斯方块、钓鱼、散步及取消都必须匹配当前局。即使同一时刻开两局、请求缓存被淘汰，旧局操作也不能修改新局或重复领取。
- 钱包及库存变动与存档在同一个 SQLite 事务提交；并发领取/购买不会重复扣币或超支。请求幂等保证网络重试不重复换装或发币；取消/结束移除局状态。
- 导入校验余额、时间、已知且唯一的库存、装备所属与槽位、纪念来源和物品关系。导入深拷贝，失败不影响当前存档；新宠物钱包与回忆为空。
- 这是本地单玩家、可自行备份与导入的经济，不是防篡改排行榜或联网货币。账号、云存档与部署仍暂缓。
