照顾与陪伴 → 宠物参加游戏 → 获得金币 → 装扮小窝 → 留下共同经历。继续完善这条循环，而不是只增加小游戏数量、阅读页或收藏计数。

- 正式菜单已有七款：接星星、连连看、贪吃蛇、俄罗斯方块、池塘钓鱼、公园散步、森林寻宝。见[游戏目录](ARCADE.md)。

- 「陪它一会儿」已有摸摸、发呆和真实纪念册回忆闲聊；B 轮换已保存的共同经历，不增加奖励或收集目标。
- 近期三键修复已覆盖自动步进中的 C 暂停，以及网络禁用后的原生按钮焦点恢复。见[步进暂停](BOARD_PULSE_PAUSE.md)和[机身键盘](PHYSICAL_KEYBOARD.md)。后续按实际回归结果维护，不重新宣称待实现。

这些是源码已交付的范围，**不代表玩家正在使用的试玩进程已经升级**，也不代表自然多日陪伴已获真人验收。

## 优先顺序

### 1. 先处理可复现的可靠性与操作问题

- 新反馈先记录：所处页面、A/B/C 操作顺序、预期与实际、能否刷新续玩、设备／字号；区分功能错误、布局问题和体验建议。
- 存档丢失、重复结算、自动续玩、未知写入被重发、按键失效优先于内容扩充。只在独立存档复现，不代操作玩家存档。
- 修复必须证明旧问题可复现，并验证相关中断／恢复边界；不为追求测试数量重新铺无差别矩阵。

**交付标准：**玩家能完成原本受阻的操作；没有重复写入、额外玩法按钮或旧档回归。问题未复现时明确写作待调查，不宣称已修。

### 2. 回到照顾与成长的完整体验

下一轮重点走查以下连贯流程，而不是继续扩手册：

1. 从小窝看懂当前最需要什么，进入菜单后知道该选哪项。
2. 喂食、清洁或起床后，看清即时状态变化；能分清状态改善、习惯间隔和成长点，避免把“没有记习惯”误解成操作无效。
3. 跨入成长期／成年期时，造型、庆祝、阶段说明和保存结果一致；刷新后阶段与形态保留，不重播成功。
4. 离开、短暂断线或睡眠后，回访解释能接回实际照顾；旧历史没有记录的部分不补造。

**当前覆盖：**首次迎接字号、[小窝／菜单建议](CARE_MENU_ADVICE.md#2026-10-21--小窝接到下一次照顾)、[主动及被动跨阶段](CARE_GROWTH_JOURNEY.md)、[起床反馈先于自动回访](RETURN_CARE.md#2026-10-21--照顾反馈先于自动回访)均已有交付与隔离回归。回访建议接到连续照顾／未知结果核对的走查也未发现新的操作障碍；具体边界和构造方式保留在[开发进度](PROGRESS.md)，不再列作待开发。

**本轮结果：**七款游戏的暂停、恢复、刷新保持、帮助/图鉴回看、放弃确认和终局收好已在独立真实 Chrome 流程中复验；森林寻宝长屏随后又完成了 LCD 内滚动、终局反馈和三键托盘联合复验。随后完成了独立临时存档的照顾—成长—睡眠—离开—回访连续走查：成长主流程 8 组、被动成长 4 组、睡眠 16 组、回访 2 组全部通过，未发现新的高置信度操作或存档问题。外部试玩提出的菜单发现性、阅读焦点、回执层级、连续游玩反馈和蛇首局提示也已分别交付或记录，不重复列作待开发；具体边界见[开发进度](PROGRESS.md)与[试玩记录](PLAYTEST_FEEDBACK.md)。

**下一项可执行工作：**连连看配错后的合法路径示例、七款首次说明第一页的陪玩间隔提示已经交付；游戏结算也已补齐本局熟悉度增加／间隔内／已熟悉的服务端回执，明确与陪玩习惯和成长分开；关闭浏览器真实等待 16 分钟的旧档／完整睡眠回执验收也已通过，见[回访验收](BROWSER_ABSENCE.md#2026-10-23-本轮运行)。下一轮继续关注自然多日陪伴、连续游戏后的成长反馈、成年后的长期目标和实体手机后台切换；出现可复现的操作或存档问题就先修复并补隔离回归。当前没有足够证据直接改贪吃蛇速度或增加新奖励；节奏拍手原型继续遵守公平性、暂停、刷新、幂等和旧档兼容门槛，不直接接入正式奖励。近阈值导入与构造离开间隔不冒充自然养大；不擅改成长速度、阈值或惩罚，不为缩短阅读删掉精确回执。

**交付标准：**发现问题后交付一个可观察的理解度／操作改进和针对性回归。自动化通过只能证明流程与断言，文案舒适度、自然成长节奏仍需实际体验。

### 3. 根据体验改善七款游戏与长期陪伴

- 贪吃蛇暂停时已补齐[相对转弯提醒](SNAKE.md#暂停时看懂相对转弯)，不改 A/C 继续、B 放弃确认的映射。俄罗斯方块也已补齐[暂停选项后果提示](TETRIS.md#暂停时先看懂所选操作)，说明旋转会继续下落、落底会固定，不改变操作。钓鱼也已补齐[暂停所选操作说明](FISHING.md#暂停时看懂所选操作)，区分恢复阶段、只读回看与放弃确认。继续关注钓鱼等待是否有反馈、暂停后回看是否过长、三键是否易误按，以及手机字号与滚动。已有水纹、鱼影、咬钩短音和本局钓获回看不再重复开发。
- 天气、季节、晨昏、偶遇和雨珠小鲤已有内容；若继续补充，先确认能带来不同的共同经历，不机械增加同类对白、资源或集齐目标。
- 自然长玩稀有度、真实声音舒适度、实体手机后台切换、系统输入法与真人读屏尚待实际体验。没有反馈时仍可进行隔离走查和修复，不把等待反馈当作整个开发被阻塞。

**交付标准：**明确改善哪段体验、为何值得增加内容，并验证三键、暂停、旧档和奖励边界；不以自动化模拟替代真人结论。

### 4. 新小游戏候选：先评估已有节奏原型

[节奏拍手](../prototypes/rhythm/README.md)已经有独立可玩原型，但**没有接入正式菜单、玩家存档、金币或成长**；不能再称“还没做原型”，也不能算正式第八款。

原型已支持同一标签刷新后核对观测并暂停，以及旧页凭据失效保护；仍只在实验服务内存保留，不是正式存档持久化或多端续玩。具体边界见原型说明。

正式接入前必须先通过：

- 无声也能理解 A/B 两种提示、C 暂停；减少动态与小屏可用。
- 键盘／触摸、低帧率、网络延迟下的公平性验证，不采用客户端自报成绩绕过校验。
- 明确会话／拍序、失焦与刷新后手动继续、结果未知不重发、幂等收好和共享额度方案。
- 角色解剖动作、旧存档兼容、陪伴门槛与纪念规则一起设计；不先上线入口再补安全。

已有[公平性评估](RHYTHM_EVALUATION.md)是实验依据，不是上述门槛全部通过的证明。未通过则继续独立实验，不为了“更多游戏”直接接正式奖励；森林寻宝已正式交付，不再当作候选。

## 每批交付与记录方式

- 仅使用 A / B / C 三键；LCD 不新增可点击玩法控件。
- 保持旧档兼容；数据库、端口、后端和网页构建均隔离。**不访问、重启或自动部署玩家试玩服务**，不覆盖玩家数据库或共享构建。
- 产品代码改动跑相关单测、类型／隔离构建、后端检查和针对性真实浏览器回归；纯文档批次核对内容与链接，不把旧版测试数量当本批新增结果。命令见[开发说明](DEVELOPMENT.md#验证与隔离构建)。
- 区分源码测试、隔离服务验收、GitHub CI 与玩家实际部署；构造存档、响应夹具、模拟视口必须如实标注。
- 测试通过后，以「草莓小熊」为 author 和 committer 提交并推送；不改全局身份、不重写历史。
- 新进展只追加到[开发进度](PROGRESS.md)；本文件仅在当前优先级或状态变化时修改。历史测试数量和逐批安排保留在[归档](NEXT_STEPS_HISTORY_2026-10-21.md)，不再堆回此页。

账号、云存档、联网社交、AI 对话和公网部署不是当前优先项；持续迭代目标不因完成某一批就视为全部结束。
