# 睡眠后的照顾指引（2026-10-19）

## 已实现

原状态页睡眠建议始终只有「正在休息；体力满后不再增加休息习惯」，无法区分体力已经恢复好，或睡着期间饱食、清洁已经偏低的情况。本批完善现有状态页，不增加菜单或玩法按钮。

- 体力未满、饱食和清洁无明显需要时，说明可以继续休息，不必急着叫醒。
- 体力实际达到 100 且无其他身体需要时，说明可以从菜单选「起床啦」，继续睡不再增加休息习惯。
- 饱食或清洁需要照顾时，说明醒来后优先做什么，并给出「先从菜单选起床，再喂食/洗澡」的实际路径。不自动叫醒、不强迫立即处理、不承诺额外奖励。
- 共用原有身体需求优先级：低于等于 25 时先选最低值，平手按既有顺序；否则按相对阈值选择。睡眠建议只考虑饱食/清洁，不邀请睡着或体力低的宠物去游戏角。清醒时原有需求、动作和提示优先级不变。
- 建议只读最近接受的服务端状态；本地时钟不会推测已经恢复满体力。旧回复不覆盖新状态，其他页面叫醒后的权威同步会更新建议。
- 没有改后端、存档、schema 11、成长/照顾数值或成年形态；没有新增写请求、定时器、死亡或待办惩罚。

## 随浏览器验收修复的读数布局

截图发现状态页固定 20px 数字列在可读字号下会把 `100` 拆成两行；原「文字未越界」检查并不能识别这一问题。

仅为阅读模式的状态数字列设置随字体缩放的最小三字符宽度、不收缩及不换行。保留状态条和原字号，不缩小数字来塞布局。新增真实浏览器文字行数检查，旧构建在 320px 普通字号的 `100` 上实际失败（两行），再验证修复后的构建。

## 2026-10-20 · 主页直接看见休息中的照顾提示

睡眠主页原来只有梦境文案，玩家需要打开菜单或状态页才知道体力已满，或者饱食／清洁需要照顾。本轮将同一份已接受状态的建议放在主页，独立于临时的入睡回执；不改梦境动作，也不把阅读提示当作新的照顾事件。

- 「最近读取 · 正在休息」明确是保存读数，不是本地计时预测。复用既有 `CareAdvice` 和身体需求优先级，不新建一套阈值。
- 舒适且体力未满时不催醒；实际满体力时说明继续睡不增加休息习惯；需要吃饭／洗澡时说明先在原菜单起床，再照顾。不自动醒来、喂食或清洁。
- 只有主页且实际睡眠时出现；菜单保留原说明。确认醒来、其他页面醒来并同步后移除；再次睡下显示新状态，较旧回复不回退。旧回复没有成长字段时也能使用。
- 提示不是按钮、弹窗或live region；普通读取不抢原生焦点／滚动位置。采用文档流和随根字号缩放的正文，不压缩字体、不盖住LCD页脚和三键。连接异常的恢复屏不展示可执行的照顾建议。
- 不增加操作请求、定时器、资源、成长点或每日压力；不改schema17、成长规则、睡眠结算、三键或旧档迁移。
