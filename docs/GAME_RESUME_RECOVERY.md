# 在途响应与手动续局（2026-10-19）

## 修复的问题

贪吃蛇和俄罗斯方块此前只在离开时清空本地运行标记。如果「继续」响应还在路上，切后台或打开玩法说明/存档盒之后收到响应，会重新写回运行标记，关闭面板后可能自动走格/下落。方块从本地暂停执行旋转/落底时，还有「服务端暂停 → 操作」两次请求，第二步可能跨过离开事件继续发送。

现在记录本地暂停代次。切后台、打开说明/存档盒/重置确认或进入存档恢复时，旧代次的续局许可失效：

- 迟到但有效的服务端响应仍更新棋盘，不丢弃、回滚或重发已经接受的操作。
- 旧响应不能重新允许连续走格/下落；回到页面后仍显示暂停，需重新按 A/B/C 决定。
- 方块两步链路被打断后不发送后续旋转/落底；已接受的暂停保留。未被打断时仍按原规则执行。
- 不新增游戏按键、确认层、奖励、存档字段或迁移；schema 仍为 11，服务端局 ID、版本校验、离开租约和幂等规则不变。钓鱼/散步沿用原有代次保护，没有借此重构全部游戏。

## 回归范围

新增 38 项应用测试：四种在途操作（蛇继续、方块继续/旋转/落底）× 三种打断（后台、说明、存档盒）× 两种返回/收包顺序，共 24 项；方块两步链路另 12 项；未打断的旋转/落底链路另 2 项。先复现 36 项失败、2 项正常链路通过，再修复。打断后检查无额外自动请求、暂停显示保留，重新明确继续后仍能运行，局 ID 未改变。

浏览器验收将实际服务接受操作后的响应暂扣，再操作真实说明/存档盒，检查迟到响应不会恢复自动运行；不要求服务端撤回已经接受的那一步。后台路径使用注入的 `document.hidden` 与 `visibilitychange` 事件：此 Chrome 自动化环境所有标签页均报告可见，因此不将这部分称为真实系统切后台验收。

本批仅验证续局竞态，不重新宣称六游戏完整通关或全部角色画面矩阵，也不是用户试玩反馈。所有写入只针对新建 `/tmp` SQLite 数据库，不操作玩家存档。
