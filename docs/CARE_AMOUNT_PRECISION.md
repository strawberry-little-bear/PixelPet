# 照顾回执与日记的数值精度

## 复现

一次实际结算九秒的睡眠，按现有每小时恢复 14 点体力，从 85 点开始，累计恢复量可能保存为 `0.03499999999999659`。服务端日记已经按去除微小浮点尾差后的两位小数显示为 `+0.04`；前端睡眠进度、起床小结直接使用 `toFixed(2)`，却显示 `+0.03`。

接近成年上限时，本次照顾实际增加的成长点也可能落在同样的半分位，导致临时回执和刷新后日记显示不一致。不是少发体力或成长，而是显示舍入策略不同。新增的三个组件回归在修复前均失败。

## 本批处理

- `web/src/careAmount.ts` 与服务端已有 `diaryAmount` 使用相同的两位小数舍入方式，仅在小数半分位处理纳单位级尾差。
- 睡眠进度、起床小结、照顾即时变化和本次成长共用该显示函数；前后需求读数保持固定两位，真实微量正增量保留 `<0.01`，不误写成零。
- 不修改服务端积分、状态、习惯、单次结算上限、成年定型或任何保存数值；不是提高养成速度，也不把显示文本写回存档。
- 原有异常回复检查继续先执行，格式化函数不代替数据校验。刷新后仍不重建临时回执，近期日记沿用原文。
- 没有新增玩法按钮、声音、奖励、存档字段或 schema 迁移。

## 验证边界

- 前端覆盖半分位两侧的浮点尾差、真实微量、非尾差边界、需求前后读数与组件源对象不变。
- Go HTTP／临时 SQLite 使用受控服务端时钟：真实调用孵化、入睡、九秒后起床，检查原始恢复量未被改成 `0.04`，日记显示 `+0.04`，幂等重播与重启回读不改历史、不重建回执。这不是自然九秒浏览器等待或多日养成。
- `scripts/check-sleep-summary.mjs` 新增桌面及 320px／双倍文字的半分位响应夹具，检查睡眠进度与起床小结都显示 `+0.04`、微量不为零、文字可达、三键约束及不重复照顾。夹具只验证显示，不冒充真实睡眠计时；同脚本保留真实短时睡眠与旧档／导入验收。
- `scripts/check-sleep-progress.mjs` 的数值预期独立按同一规则计算，仍核对服务端原始结果，不从界面文本反推存档。
