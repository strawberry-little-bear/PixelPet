# 回访小结的响应保护

## 修复范围

已提供的 `returnRecap` 此前没有进入响应安全检查。损坏的历史状态可能在读取 needs、调用 `toFixed` 或日期 `toISOString` 时使页面异常；标为待读的坏记录也可能在展示之前被自动请求确认。

现在先检查历史记录，再接收成功回复或触发自动确认：

- 小结是对象，ID 为非空字符串，两端时间为可显示的非负整数时间戳。
- `before` / `after` 都有四项有限的 0–100 状态、已知阶段/形态，以及有限且有界的成长、休息、统计时长。
- 历史 `sleeping` 缺失/null 仍表示「未记录」，不按当前睡眠状态补造。整个小结缺失/null 仍兼容，未知额外字段原样保留。
- 已提供的 `recapPending` / `recapClaimed` 必须为布尔值。

普通读取错误仍进入连接恢复；写回复异常仍表示「可能已保存」，A/C 暂停，B 只 GET `/api/state` 核对。自动确认回复丢失/损坏时，B 核对本身不重发确认，不补播回访或成功动画。恢复后仍可通过三键菜单主动查看已保存的两页历史。本批不改变之后普通前台心跳对仍待读记录的既有处理，不宣称永久屏蔽同一记录的后续确认。

这是**显示安全检查，不是完整业务一致性校验**：不重建历史，不新增时间先后/成长门槛规则，不声称能识别所有伪造但形状合法的回复。未改服务端实现、离线衰减/睡眠恢复数值、schema 12、三键操作或成年定型。

## 回归与复现

- 请求解析新增 192 项：40 种异常 × state/visit/action/recap-read 四路径 = 160；8 种兼容回复 × 四路径 = 32。检查异常类别、每次仅一次请求、合法数据不改写。修复前为 160 失败 / 32 通过。
- App 新增 8 项初次读取/轮询/已执行照顾/未转发照顾的异常恢复；另新增 4 项自动确认已执行/未转发 × 日期/needs 异常。确认连续坏读取不解锁，正常 B 核对不重做照顾或确认，菜单历史仍可读。
- 永久浏览器入口仍为 `scripts/check-growth-response.mjs`，复用独立库/端口。新增 8 组坏回访数据、4 组确认结果未知与两页手动查看、4 组真实离开结算及旧式睡眠字段兼容；保留原有成长/照顾 42 组。
- 结算使用**受控 30 分钟时间夹具**：先在本轮新建的临时库导入测试宠物并记录访问，再在无浏览器页面时整体平移保存的时间戳及访问时间；随后由真实后端处理 visit、衰减/睡眠恢复、保存历史与确认。缺失/null 的历史睡眠字段通过网络响应注入，数据库原历史保持完整。不是自然等待 30 分钟，也不是玩家存档迁移或真人验收。
- 浏览器检查清醒时体力下降、睡眠时体力恢复、饱食下降；实际成长/统计时长增加、仅睡眠增加有效休息，醒来后的历史仍保留结算时的睡眠状态；没有额外金币。单次异常确认及 B 核对/手动阅读序列内只发送一次确认，普通读取与未知写入恢复路径区分，三键至少 44px、LCD 无新增玩法点击控件。390px 普通字号与 320px 双倍根字号按场景分配，不是全部数据/布局组合。

## 重复运行

先通过前端测试、类型检查和生产构建，再构建测试二进制：

```sh
./.tools/go/bin/go build -o /tmp/pixelpet-return-response ./cmd/pet
(cd web && ./node_modules/.bin/vite build --outDir /tmp/pixelpet-return-response-web)
PIXELPET_TEST_BINARY=/tmp/pixelpet-return-response \
PIXELPET_TEST_WEB=/tmp/pixelpet-return-response-web \
PIXELPET_PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs \
node scripts/check-growth-response.mjs
```

脚本只修改自己 `mkdtemp` 的数据库，不接受玩家服务 URL，退出时关闭自己的浏览器与服务。结果 JSON 保留本轮临时库、端口、运行范围及逐组记录。可用 `PIXELPET_TEST_SCOPE=return` 单跑新增的 8 组确认/离开兼容场景；默认 `all` 才是包含全部异常读取与原回归的 58 组。

玩家数据库不重置、不导入覆盖，原后端不重启、原页面不刷新。构建更新忽略的 `web/dist`，共用该目录的服务在之后刷新时可能使用新前端，不能说完整运行环境隔离或原后端已部署。
