# 存档盒运行信息

[文档导航](README.md) · [开发运行](DEVELOPMENT.md) · [连接恢复](SAVE_RECOVERY.md)

打开机身外的「存档盒 → 运行信息」可以查看连接诊断、最近成功同步时间、浏览器访问地址，以及网页和后端各自的构建标识。长内容在存档盒内滚动；C 收起，原生 Tab、Enter、空格仍可操作工具区。LCD 内保持 A / B / C 三键。

## 怎么读

| 项目 | 含义 |
| --- | --- |
| 存档连接 | 使用游戏已有的同步结果，区分尚未读到存档、最近同步正常、暂时连接不上、保存结果待核对、存档需要修复、服务时间待校准。版本查询成功不会改变这个判断。 |
| 最近成功同步 | 当前页面接受有效状态回复时的本机接收时间。不是宠物存档时间、后端时钟或持续在线证明；页面刷新后重新记录，过期版本回复不更新时间。 |
| 网页地址 / API 入口 | 浏览器看到的 origin 和 `/api`。开发代理可能转发到另一台后端，不能据此推断后端监听地址或数据库位置。 |
| 网页构建 | 生产构建时的 Git 提交及工作区改动状态。Vite 开发模式只标明可热更新；无法取得 Git 元数据时显示未记录。 |
| 后端构建 | Go 二进制中可用的 VCS 提交及改动状态。禁用 VCS 信息或没有元数据时显示未记录。 |
| 支持的存档格式 | 后端代码支持的 schema，来自 `game.Schema`，不是当前数据库中玩家存档的实际版本。 |

提交标识用于辨认正在运行的构建，不代表 GitHub 最新提交，也不证明网页与后端一定来自同一版。含未提交改动的构建只能标明基准提交与改动状态，不能还原那批改动的精确内容。

## 查询与恢复边界

- 仅在展开运行信息或主动重新读取时请求 `GET /api/runtime`；收起、关闭存档盒或页面卸载会取消请求并丢弃迟到回复。十秒未完成时停止等待，允许重新读取。
- 接口只返回支持的 schema 和公开的 VCS 构建字段，设置 `Cache-Control: no-store`。它不访问数据库、不推进宠物时间、不读取文件路径或环境变量。
- 旧服务不支持该接口、返回无效数据或查询失败，只提示版本信息不可用；照顾、备份与原有恢复流程保持各自的状态。
- 保存结果未知时，C 收起存档盒后按 B 核对；B 在存档盒打开时也允许安全读取。只读当前存档，不重发原操作。时间异常时先校准运行后端的电脑。
- 打开存档盒会撤销实时游戏的本页运行许可，关闭不会自动继续。运行信息读取本身不发送游戏操作；服务端会话与本页暂停呈现不是同一标志。

## 回归方式

组件回归：`RuntimeInfo.test.tsx`、`RuntimeInfoApp.test.tsx`；接口回归：`internal/httpapi/runtime_test.go`。后端用 nil 数据库及禁止调用的时钟验证查询独立性。

真实浏览器专项与其他脚本一样，需要[隔离构建](DEVELOPMENT.md#验证与隔离构建)：

```sh
PIXELPET_TEST_BINARY="$CHECK_DIR/pixelpet" \
PIXELPET_TEST_WEB="$CHECK_DIR/web" \
PIXELPET_PLAYWRIGHT_MODULE="/absolute/path/to/playwright/index.mjs" \
node scripts/check-runtime-info.mjs
```

脚本创建临时数据库和随机端口，检查桌面、320px、短屏双倍根字号、减少动态、强制颜色、模拟触摸、原生键盘、旧服务及迟到查询。连接失败用页面网络拦截模拟；未知写入由真实服务先提交再丢弃回复，核对不重复写入；散步使用构造初始宠物和真实开局，检查工具区关闭后保持本页暂停，不自动步进。不访问玩家服务；自动化不能代替实体手机、真人读屏或自然长期体验。
