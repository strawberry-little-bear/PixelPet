# 三键提示音容错（2026-10-19）

## 复现与修复

原三键提示音在 `try/catch` 内调用 `void context.resume()`，却未接住它的异步拒绝。独立测试库的真实 Chrome 中，注入一次音频恢复拒绝后按 A，收到 `audio permission blocked` 页面错误；同步 `try/catch` 不能处理这个 Promise。音频不是存档操作，不应影响照顾或导航。

现在独立管理可选提示音：

- 保持默认关闭、沿用本地声音偏好；关闭时不创建音频上下文。
- A/C 的 520Hz、B 的 740Hz、原音量与 100ms 短音保留，不新增背景音乐或音频玩法依赖。
- 恢复音频成功后才创建音符节点；不存在、构造失败、恢复失败、节点异常或关闭失败均静默降级，三键与保存不等待音频。
- 同一次待恢复音频只请求一次恢复，期间只保留最新按键；超过 250ms 不补播迟到反馈。250ms 是可选音效的丢弃上限，不是游戏判定窗口或实际设备延迟保证。
- 关声音、切后台、组件卸载会作废待播按键，正在播放的节点停止并断开；正常短音结束也断开。重新打开声音/回前台不重播旧按键，下一次正常按键仍可发声。
- 已解锁后快速连续操作不会叠加同类声音：新的按键提示会替换仍在播放的旧按键提示，新的咬钩提示会替换旧咬钩提示；按键与咬钩两类提示彼此独立，仍保留一次按键后的咬钩反馈。
- 卸载关闭拥有的上下文；支持 React StrictMode 的效果清理后重新初始化。已有 IME/长按/焦点过滤继续在音频之前生效。

没有修改玩法、成长/衰减/奖励参数、存档或 schema 12；LCD 与机身三键没有新增控件。声音设置不写玩家 SQLite。
