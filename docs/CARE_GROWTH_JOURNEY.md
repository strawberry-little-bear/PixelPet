# 照顾跨阶段与恢复：浏览器真实接口回归

## 如何构造，哪些是真实操作

- 脚本自行申请临时端口、创建临时数据库、启动并最终关闭自己的 Go 子进程。只接受显式指定的独立二进制及前端构建，不连接原试玩页、不操作玩家库。
- 每组从真实 reset / hatch 接口取得合法存档，再导入**构造的**历史：成长点 23.95、指定的舒适度/照顾习惯，以及与之相容的相遇和纪念时间。
- 使用机身 A/B/C 喂食，真实服务端加习惯与成长，跨入成长期。等待喂食动画与随后成长动画，C 只跳过表现；刷新不重放、不再发照顾请求。
- 导出这一只宠物的存档，**显式把成长点推进到 71.95**，再导入、刷新。通过真实三键洗澡跨入成年，检查加点封顶、定型时间、四种形态、定型依据和唯一纪念。不是连续自然长到成年，也不是用假接口直接返回成年。
- 精确重放刚才真实洗澡请求及 generation，检查幂等确认一致，实际存档不重复增加照顾/纪念。
- 再喂一次：30 分钟间隔内仍真实改善身体状态，但不重复计习惯/成长；成年定型记录不变。
- 三键入睡、真实短暂等待、刷新并读取，检查体力 `+14/h`、饱食 `−3/h`、清洁 `−2/h`、心情不变，以及按恢复量 `/28` 比例累计的休息习惯。醒来后导出、原样导入备份，确认 generation 更新、定型记录保持、刷新不重播庆祝。
- 清醒时也通过真实短暂等待和两次 visit，独立核对四项衰减、舒适度积分带来的被动成长；不因被动结算虚增主动照顾次数/习惯。
- 最后用三键打开成长手册第 3 页，核对真实返回的定型依据。

**边界：** 历史习惯和两处阈值由测试输入构造，不证明这些习惯来自真人多日养成。时间流逝检查只有几百毫秒至数秒的真实间隔，不代替自然长时离开、12h 上限、自然跨阶段、真人读屏/实体手机或真人长玩舒适度验收。既有 Go 成长旅程仍负责完整模拟时间、不同照顾策略的长期演进覆盖。

## 运行

先独立构建 Go 二进制和前端（不要覆盖运行中的 `bin/pixelpet` / `web/dist`），再指定：

```sh
PIXELPET_TEST_BINARY=/absolute/temp/pixelpet \
PIXELPET_TEST_WEB=/absolute/temp/web \
PIXELPET_PLAYWRIGHT_MODULE=/absolute/node_modules/playwright/index.mjs \
node scripts/check-care-growth-journey.mjs
```

需要可启动的 Chrome。未设置 Playwright 模块路径时使用普通 `playwright` 包。输出临时产物目录，保留结果 JSON、Go 日志及桌面/手机定型依据截图；结束时关闭本脚本创建的浏览器、服务器。
