# 商店主动操作的阅读定位

## 复现与修复（2026-10-20）

独立旧构建、真实 HTTP/Chrome 复现：320×700、根字号 28px（默认的两倍）下，按机身三键进入商店，当前分类顶部为 **−373.4px**，机身键可见但选项已在视口上方。这是长阅读页点击机身键后的文档滚动问题，不是商城分类、金币或购买数据错误。

补充短屏验收时又复现：320×380、双倍字号下，真正穿戴后的 `.shop-decision` 顶部为 **−47.7px**，反馈仍在屏幕上方。已纳入修复及浏览器断言，不只检查购买接口是否成功。

沿用 `useReadingViewport`，只在明确操作时消费一次性定位请求：

- 进入商店、A 换分类、C 返回分类：定位当前选中行。
- 进入分类、A 下一件、A/C 取消购买确认：定位当前物品标题；空分类定位空态标题。
- B 打开购买确认、查看余额不足/睡眠/已领问候提示、使用/收起已拥有物品：定位本次决策或操作反馈。
- 购买确认同时写出**物品名称和金币价格**，不要求靠视口外的标题辨认即将买什么。第二次 B 才提交，A/C 仍只取消。

已完整可见的目标不滚动；不改变自然文档布局、字号、内部高度或原生按键焦点。长文仍通过自然滚动阅读，不承诺短屏同时容纳所有文字与机身键。

请求绑定存档代次/生命周期、分类、物品 ID、确认状态，目录另绑定选中分类。被后台、恢复页或换档阻断也只消费一次，不在普通读取、帮助关闭、重新联网或返回前台后重放。普通目录重排、外页购买/入睡、报价失效继续使用原有稳定 ID 与确认取消保护，**不增加自动购买、自动穿戴或额外领取**。

无后端、schema、价格、成长、奖励规则、偏好或按键数量改动；旧服务没有商城时定位原说明标题。
