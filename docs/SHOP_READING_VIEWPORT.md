# 商店主动操作的阅读定位

## 复现与修复（2026-10-20）

独立旧构建、真实 HTTP/Chrome 复现：320×700、根字号 28px（默认的两倍）下，按机身三键进入商店，当前分类顶部为 **−373.4px**，机身键可见但选项已在视口上方。这是长阅读页点击机身键后的文档滚动问题，不是商城分类、金币或购买数据错误。

补充短屏验收时又复现：320×380、双倍字号下，真正穿戴后的 `.shop-decision` 顶部为 **−47.7px**，反馈仍在屏幕上方。已纳入修复及浏览器断言，不只检查购买接口是否成功。

沿用 `useReadingViewport`，只在明确操作时消费一次性定位请求：

- 进入商店、A 换分类、C 返回分类：定位当前选中行。
- 进入分类、A 下一件、A/C 取消购买确认：定位当前物品标题；空分类定位空态标题。
- B 打开购买确认、查看余额不足/睡眠/已领问候提示、使用/收起已拥有物品：定位本次决策或操作反馈。
- 购买确认同时写出**物品名称和金币价格**，不要求靠视口外的标题辨认即将买什么。第二次 B 才提交，A/C 仍只取消。

已完整可见的目标不滚动；不改变自然文档布局、字号、内部高度或原生按键焦点。长文仍通过自然滚动阅读，不承诺短屏同时容纳所有文字与机身键。

请求绑定存档代次/生命周期、分类、物品 ID、确认状态，目录另绑定选中分类。被后台、恢复页或换档阻断也只消费一次，不在普通读取、帮助关闭、重新联网或返回前台后重放。普通目录重排、外页购买/入睡、报价失效继续使用原有稳定 ID 与确认取消保护，**不增加自动购买、自动穿戴或额外领取**。

无后端、schema、价格、成长、奖励规则、偏好或按键数量改动；旧服务没有商城时定位原说明标题。

## 选择播报与购买后的反馈（2026-10-25）

独立无障碍走查发现：两件可购买物品的 `.shop-decision` 都只写“B 购买 · 下一步确认”，A 换物品后，已有播报区不包含商品名或位置。现在沿用同一个 `role="status"`，设置 polite、atomic，并加入仅供辅助技术读取的当前分类、位置、物品名、部位、价格／已拥有状态及 A/C 操作。确认期间提示 A/C 取消；B 的实际操作继续使用原有可见文案。没有再加一处竞争的播报区，普通需求／余额读取若未改变选择或操作，也不改写该节点。

真实浏览器交叉回归另确认了一个已有短屏问题：320×380、双倍根字号下，第二次 B 购买成功，确认详情收起后文档变短，反馈顶部落到 **−94.1px**。本批改动前的隔离构建和初版改动得到相同位置。现仅在购买明确成功后，为当前物品请求一次反馈定位；后台、窗口失焦、pagehide 或存档恢复中断会使待完成的定位失效。失败／结果未知、普通读取和刷新不会重放购买或反馈定位，仍需两次 B 购买、再次 B 使用。

- 选择播报新增 5 项在旧实现上均失败；购买成功定位的更新断言也在旧实现失败。修正后相关前端 **7 文件／202 项**通过，包含延迟响应跨后台／失焦／页面恢复，以及被拒绝／结果未知不定位、不重发。
- TypeScript、独立 Vite／Go 构建、Go 无缓存全量 race 和 vet 通过；脚本语法和隔离启动保护 **2/2** 通过。
- Chrome／真实 HTTP／临时 SQLite **2/2 组**通过：1200×700／14px 与 320×380／28px，后者启用强制颜色和减少动态。覆盖当前 8 分类、物品与空态、确认取消、真实购买／穿戴／收起、刷新与普通同步；检查选择播报文本、节点稳定性、文字边界、焦点、滚动及三键约束。每组经济操作恰好 3 次，只购买扣价一次。已目视检查两种尺寸的购买确认截图。
