# 未同步终局的放弃保护（2026-10-19）

## 复现与修复

上一批 [小游戏同步](GAME_SESSION_SYNC.md) 会在接受新读取后清掉旧放弃确认，但仍有一个写入窗口：页面甲打开未完成对局的「放弃」确认，页面乙把同一局玩到终点，甲尚未轮询就按 B。原有局 ID 校验无法区分同局进度，旧命令会删除尚未收好的结果。本批先用存储测试复现四种游戏全部失败，再补服务端前置条件及恢复流程。

新页面发送 `cancel-play` 时附带请求头 `X-PixelPet-Cancel-If: unfinished`，不增加 JSON 命令字段、存档字段或按钮。新服务在原有存档代次与局 ID 检查内，判断贪吃蛇/俄罗斯方块结束、钓鱼三竿结束或散步到达终点；若已结束，返回 **409 / `game_finished`** 与当前存档代次。整笔事务回滚，不删局、不推进时间、不写快照/请求缓存/回访记录，也不自动结算照顾或金币。六种未完成游戏仍可正常确认放弃，不发奖励。

页面区分「已明确拒绝」与「响应丢失、结果未知」：

- 明确拒绝后清掉旧确认、停止本地运行，提示「本次放弃未执行」，而非声称可能已保存。
- A/C 不写入；B **只读**当前存档，不重发 cancel，不自动领取。
- 读取失败或读到较旧版本，继续暂停并保留已拒绝提示；成功读取后显示实际结果，再明确按 B/C 收好。
- 若 409 响应本身丢失，仍只能提示结果未知；读回权威状态之前不猜测是否执行。

## 兼容性与适用范围

- schema 仍为 11；不改旧档、成年固定形态、奖励公式、每日额度、游戏时序或成长参数。
- 前置条件是传输元数据，`Action.RequireUnfinished` 标记为 `json:"-"`；请求 JSON 维持原样，严格解码仍拒绝客户端提交 `requireUnfinished` 等未知字段。
- **新页面 + 新服务**才具备这项保护。旧客户端不带头，仍保留原来主动丢弃终局的行为；新页面连接旧服务时，请求头会被忽略，JSON 仍可兼容，但没有终局保护。需要重启/升级 Go 服务才会生效，不能把构建新二进制当作已经升级运行进程。
- 非空无效值或把此头用在非 `cancel-play` 动作上，返回 400 且不写入。原有 `save_changed` 与局 ID 边界保留；不是通用多设备同步、权限控制或所有动作的进度锁。
- 本轮未重启玩家服务，未对玩家存档导入、重置或代操作。
