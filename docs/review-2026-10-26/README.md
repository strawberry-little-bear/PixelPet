## 3. P0-1 机身高度跟着内容走

### 现象

同一个界面，**运行中和暂停时不是同一台机器**。

![方块运行中：516px，两列排布，按键在首屏](../playtest-2026-10-26/tetris-running.png)
![方块暂停：机身 1237px，按键在 y=1398](../playtest-2026-10-26/tetris-paused-desktop.png)
![手机 390×844：机身 1201px，按键在 y=1302](../playtest-2026-10-26/tetris-paused-mobile.png)

按 C 暂停的那一刻，机身从 516px 变成 1237px，棋盘上方的信息（目标 / 速度 / 结算门槛 / 按键说明）从两列变成竖排堆叠，三个键从 y=688 掉到 y=1398。

### 机制

`readability.css`：

```css
.device-stage.reading-mode { height: auto; }
.reading-mode .device      { height: auto; }
.reading-mode .lcd         { height: auto; }
.reading-mode .lcd-content { height: auto; }
```

`App.tsx:2432` 的 `readingMode` 除了「非游戏页」，还把**暂停 / 结束 / 结果**和**不计时的接星星**都算进来：

```js
const readingMode = page !== "game" || abandoning || uncertain || unavailable || corrupt
  || treasure || pet?.game?.kind === "tiles" || (pet?.game && !pet.game.kind)
  || (snake && (snake.paused || snake.end || snakeSession !== pet?.game?.id))
  || (blocks && (blocks.paused || blocks.end || tetrisSession !== pet?.game?.id))
  || (walking && (walking.paused || walking.beat === 72 || walkSession !== pet?.game?.id))
  || (fishing && (fishing.paused || fishing.phase === "done" || ...));
```

于是「让文字能读」的规则同时作用到了「棋盘 + 信息面板」这种不该流式排布的界面上，机身被撑开。

**只有森林寻宝是例外**，它在 `treasure.css` 里另给了固定高度：

```css
.device-stage.treasure-mode .screen-bezel { height: 460px; }
.device-stage.treasure-mode .lcd-content  { height: 380px; overflow-y: auto; }
```

所以寻宝机身恒为 699、内容内滚、按键在首屏——**这就是现成的正确做法**。

### 复现

1. 一起玩耍 → 俄罗斯方块 → B 进入（开局即暂停）。
2. 量 `.device` 高度：**1237**。
3. 按 C 继续 → **516**；再按 C 暂停 → 回到 **1237**。
4. 手机视口 390×844 重复：暂停 1201、整页 2236、按键 1302。

### 建议

1. **暂停 / 结束 / 结算三类屏幕不要走 `height: auto` 分支**，改抄寻宝的固定机身 + `overflow-y: auto`；机身建议保持在 516–700 之间。
2. 真正需要长阅读的只有状态第 2 页、成长手册、纪念册、菜单——这几页给一个**固定上限**（例如 900px）并让 `.lcd-content` 内滚，而不是无限 `auto`。
3. 状态第 2 页本身也够拆成「时间与状态」和「共同生活回顾」两页。
4. 接星星因为 `pet.game.kind === ""` 会**永远**处在阅读模式（619px），建议单独处理，让它和方块运行中一样是 516。

### 验收点

- 俄罗斯方块：暂停 / 运行 / 结束三态的 `.device` 高度差 ≤ 40px，按键始终在首屏（900×1000 与 390×844 都要）。
- 状态第 2 页：390×844 下整页 ≤ 2 屏，或明确内滚且按键可见。
- 不出现「内容溢出后被 LCD 裁掉」的情况（见 [附录 C](#附录-c-一条待确认观察)）。

## 4. P1 问题

### P1-1 接星星：亮星每 900ms 换一格，说明却说「不必等落到底」

**现象**：屏幕提示「伙伴在中间；A 移到右边」，照着按 A 再按 B，仍然是「差一点！再试一次。」

**机制**（`internal/game/game.go`）：

```go
beat := (now.UnixMilli() - s.Game.StartedAt) / 900
if beat <= s.Game.LastBeat { return "", errors.New("等下一颗星星落下再接哦") }
s.Game.LastBeat = beat
if int(beat%3) == a.Lane { /* 接住 */ } else { /* 差一点 */ }
```

命中用的是**按下 B 那一刻**的 `beat % 3`，而屏幕上的「右边」是上一拍的位置。900ms 之后它已经换了格，提示文字跟着变，但玩家读完再按键通常已经跨拍。

**对照实验**（同一局，5 轮）：

| 打法 | 结果 |
| --- | --- |
| 按屏幕提示：读位置 → 按 A → 按 B | **0 / 3** |
| 同一拍内完成：读 `beat%3` → 连按 A → B，全部压在 100ms 内 | **2 / 2** |

最终本局「一起接住了 2 颗星星」。

**问题在于文案与实现相反**：说明写「移到亮星下面就能按 B，**不必等落到底**」，听起来亮星会等你；实际是「跟着跳动的亮星走，并在同一拍内按 B」。

**建议**（择一）：

- 改成回合制：亮星停在原地直到玩家动作，接空才算一轮；
- 或保留节拍，给 2 拍宽限（`beat` 与 `beat-1` 都算命中）；
- 无论哪种，说明改成「亮星每拍换一格，要跟着它走」。

**验收点**：新玩家只读说明、不读源码，5 轮能稳定接到 ≥3 颗。

### P1-2 回执信息层级：重点被数值表和免责说明淹没

**现象**：每个动作都附一张四项数值表，**即使全部「不变」**。

入睡回执原文：

```
饱食  91.11 → 91.11  不变
心情  99.93 → 99.93  不变
清洁  86.41 → 86.41  不变
体力  68.41 → 68.41  不变
本次没有新增成长点
休息习惯：本次不计入
本次切换不计休息习惯；睡着期间按实际恢复体力记录。
记录数值：成长 +0.00 点 · 休息习惯：+0
```

真正有信息量的是一头一尾两句（「晚安，安心睡一会儿。」「它睡眼蒙眬地望望你」），中间被表和说明冲淡。

![喂食回执](../playtest-2026-10-26/feed-receipt.png)

行数统计：喂食回执 12 行、散步结算 **25 行**（含 4 行数值 + 3 段「不代表本局一定得币」类说明）、接星星结算 20 行。

**建议**：

1. 数值表只在**有变化**时出现（入睡这种全「不变」的直接省掉）；
2. 免责说明折进第二页（A/B 翻页），回执首页只留：标题 + 一句人话 + 金币 / 成长；
3. 标题行已经在做（「饭团已吃好 · 本次不记习惯」），保持这个方向。

**验收点**：任一动作的回执首页 ≤ 6 行；入睡回执不出现「不变」表。

### P1-3 状态第 2 页是一张数据报表

一页里塞了 7 组内容：四项消耗速率、共同生活回顾 5 格、此刻舒适度、一起生活的下一步、共同经历统计 4 格、**七款游戏各自局数（7 行 ×2）**、最近保存的回忆，外加 6 段说明。

![状态页第 2 页（桌面）](../playtest-2026-10-26/status-page2-desktop.png)

作为「看看状态」这个入口，玩家想知道的是「它现在好不好」，但第一屏全是「−3 / 小时」。

**建议**：「各游戏共同经历」7 行移到成长手册（那里已有更紧凑的 `接星星 ●○○○○`）；本页首屏只留四项状态 + 舒适度 + 一句建议。

### P1-4 连玩三局只有第一局算数

| 局 | 结果 |
| --- | --- |
| 接星星 | 成长 **+0.25**、陪玩习惯 +1 |
| 公园散步 | 陪玩完成 · **本次不记习惯**、成长 +0.00、「记录时约还需 26 分钟」 |
| 池塘钓鱼 | 陪玩完成 · **本次不记习惯**、成长 +0.00、「记录时约还需 20 分钟」 |

同一次坐下玩三局，后两局回执第一行就是「本次不记习惯」，读起来是「白玩了」。透明是好事（写明了还需多久），但正反馈断了。

**建议**：不给成长点也可以给别的反馈（熟悉度 / 纪念 / 一句变化），别让第一行就是否定句；或把「本次不记习惯」降级成第二行的小字。

## 5. P2 问题

### P2-1 俄罗斯方块 8 行盘面过浅

6 次「落到底」（未左右移动）就顶到顶结束，消除 0 行 → 0 金币、不计陪伴、不进共同游戏记录，全程约 20 秒。2 行的门槛在 8 行盘面上不容易达到。

![方块盘面](../playtest-2026-10-26/tetris-board.png)

落底预览（「落底预览：本块落下后暂不消行。按 B 才固定。」）是本轮最好的新增之一，建议保留。

### P2-2 钓鱼首竿等待 31.1 秒

脚本从按 B 抛竿到出现「咬钩啦」计时 **31.1 秒**。等待期间只有「还没咬钩；鱼影只是风景」和轮换的环境句（「鳍轻扶竿架，在浅水边陪你等。」「水纹一圈圈散开，不急着提竿。」）。

三竿都中，鱼名与描述（丝带泥鳅 / 青苇小鲦 / 柳影小鳉）质量很好。31 秒对「随手玩一下」偏长，建议把首竿压到 10–15 秒。

### P2-3 文案三处

1. **物种条件句用在当前角色身上**：我是海豚宝，说明页写「**换成**海豚伙伴时走浅水道：A 跃水、B 下潜。」建议直接写「你是海豚伙伴，走浅水道：A 跃水、B 下潜。」
2. **一晚三个季节**：小窝「秋日小事 · 树影换了新的颜色」、公园「虚构风景 · 冬 · 晴 · 白昼」、钓鱼「虚构风景 · 夏 · 晴 · 晨光」。前两个有「虚构风景」前缀，但玩家读到的是三个矛盾季节。
3. **成长日记是日志**：最新一条「早安！本段休息实际结算 <0.01 小时，恢复体力 +0.04，休息习惯 +<0.01，期间成长 +<0.01 点（含自然成长，非起床奖励）。」同页另一条「收好海边贝壳，花费 20 金币」就正常得多。

![成长日记](../playtest-2026-10-26/journal-entry.png)

### P2-4 手机端九宫格看不全

390×844 下 LCD 内容 476px、可视 284px，需内滚；选中会自动滚到可见（验证 `scrollTop` 会跟着变），但玩法要求比较「周围八格有几件」，看不到全盘会削弱推理。

## 附录 B 测量方法

在页面内用 `getBoundingClientRect()` 读取，避免受缩放和视口影响：

```js
const st = document.querySelector('.device-stage');
const d  = document.querySelector('.device');
const c  = document.querySelector('.lcd-content');
const b  = document.querySelector('.device-buttons');
({
  stageClass: st.className,              // 看是否 reading-mode / treasure-mode
  deviceH: Math.round(d.getBoundingClientRect().height),
  contentScroll: c.scrollHeight,          // > clientHeight 且 overflow:auto = 内滚
  contentClient: c.clientHeight,
  keysTop: Math.round(b.getBoundingClientRect().top),
  docH: document.documentElement.scrollHeight,
});
```

设计基准：`.device` 392×516、`.lcd-content` 204px、`.device-stage` 552px。**任何页面 `deviceH` 明显超过 516 且不是内滚，就是本文档 P0-1 说的情况。**
