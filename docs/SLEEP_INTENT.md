# 睡眠操作意图保护

2026-10-19。修复多页面同时照顾时，旧菜单的「睡个好觉」可能变成叫醒、旧「起床啦」可能反而入睡的问题。

## 行为与兼容

- 原 `sleep` 是切换动作；现在前端随入睡/起床请求携带最近读取的睡眠状态，服务端在同一存储事务内、应用动作前核对。不匹配则返回 HTTP 409 / `sleep_changed`，不执行相反的照顾。
- 使用传输头 `X-PixelPet-Sleep-If: awake | sleeping`，与已有存档代次校验并用。只用于 `sleep`；非法值或用于其他动作返回 400。内部 `ExpectedSleeping` 不序列化为动作 JSON 或存档，不增加 schema，仍为 12。
- 旧调用方没有这个头时仍沿用原切换行为；**保护需要更新后的前后端共同工作**。旧服务会忽略新头，不能声称它已具备本保护。本批不重启玩家服务或自动部署。
- 不匹配的事务整体回滚：不落盘时间结算、休息/成长、日记、出入场记录、小结、奖励或请求缓存；拒绝不占用 request ID。重新读取时照常按已有规则结算时间。
- 成功请求重复 ID 仍返回原已保存回执，不能因随后叫醒而重放入睡。多个不同 ID 的相同旧意图并发提交，也只能第一次改变状态，其余明确拒绝。
- 使用既有恢复页，说明「本次入睡或起床未执行」。B 只读取当前存档，既有定时读取也可核对；没有自动重试原操作或播放成功动作。恢复读取失败时保留确定的拒绝，而不是改口声称可能保存。
- 真正丢失响应仍属于结果未知：已保存的入睡/起床不撤回，不伪装成已拒绝；核对后仍不重复执行。状态读取成功后回小窝，玩家重新选定动作才提交新的意图。
- 恢复页底部改为「B 读取存档 · 不重做操作」，读取中显示「正在读取 · 不重做操作」。这也修正既有连接恢复时仍提示无效 A/C 导航的问题；不是新增控件或自动照顾。
