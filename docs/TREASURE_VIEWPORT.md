# 寻宝选格与探索反馈可见性（2026-10-23）

## 复现

第七款原先已检查文字裁切和横向溢出，但验收截图前主动滚动目标，没有验证**实际按键后**目标仍在视口内。真实 Chrome 的独立旧构建复现：320px 普通字号按 A 后选格上沿约 −64px，320px 双倍根字号约 −553px；机身按键仍在视口内。不是探索数据出错，而是自然高度网格与远处机身按键之间的阅读定位问题。

## 修复边界

- 仅有效的寻宝游戏页增加 `treasure-mode`；LCD 内容区固定为桌面约 380px、700px 以下约 284px 并在内部滚动，三个机身按键保持正常文档流，不复制按键，不在 LCD 新增点击控件。
- 明确继续、A 选格、B 成功保存探索分别发起一次定位：选格、上次探索结果或终局收好提示。先在 LCD 内滚动目标，只有整个 LCD 仍在页面视口外时才滚动页面；不改变原生焦点，不使用平滑动画。
- 探索结果取自已保存的最后一个实际探索格；刷新后仍可回看，不把终局揭示当作找到。下一格仍按原规则跳过已探索格；不改地图、步骤、奖励、成长或存档 schema。
- 普通同步、刷新首次读取、后台恢复不发起或重放定位；被帮助/失焦/后台打断的迟到继续或探索回复只接受已保存进度，不恢复运行许可或抢阅读位置。拒绝的探索不伪造结果。
- 成功提示保留在 LCD 内的文档流中，错误提示仍立即显示在视口顶部并保留警报语义。规则、放弃确认、恢复界面、存档盒及其他游戏不应用寻宝固定高度和内部滚动样式。
- 大字仍使用文档滚动，**不承诺九格始终全部同屏**。自动定位保障已测视口中的当前目标及三键可用，不等于任意极短屏幕、实体手机或读屏认证。

## 回归方式

`TreasureGame.test.tsx` 补充明确输入、拒绝和迟到回复的集成测试；`TreasureViewport.test.tsx` 覆盖一次性消费、焦点不变、按键遮挡边界、旧局/缺失目标/后台/恢复不重放。

`scripts/check-treasure-viewport.mjs` 使用临时 SQLite、随机端口、独立构建和真实 Chrome，**断言前不滚动目标**。六组覆盖桌面1200×700、手机320×700/320×380、根字号14/28px，以及短屏大字强制颜色，桌面普通字号使用默认动态效果，其余减少动态效果：

- 三键继续、十次 A 循环、B 探索、暂停/规则返回、刷新暂停、终局和明确收好。
- 原生 Enter/Space 操作机身 A 后目标可见、焦点保留。
- 选格/结果/终局提示可在 LCD 内滚动到可视范围，三键保持正常文档流且不被内容覆盖。
- 主动滚动阅读后经过普通同步不跳页；无横向溢出、文本裁切、LCD 点击控件或运行异常。
- 明确标注的模拟400拒绝不会推进真实存档或伪造结果；错误立即可见且不盖三键。
- 离开寻宝和进入规则后不遗留停靠类。

前端专项先覆盖内部滚动和不触发页面级滚动；真实 Chrome 需要使用当前版本后端二进制和独立构建复跑，旧构建无法作为本次布局修复的通过证据。完整回归和限制见 `PROGRESS.md`。

复跑需先准备独立构建，不能传玩家服务地址：

```sh
PIXELPET_TEST_BINARY=/absolute/tmp/pixelpet \
PIXELPET_TEST_WEB=/absolute/tmp/web \
PIXELPET_PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs \
node scripts/check-treasure-viewport.mjs
```
