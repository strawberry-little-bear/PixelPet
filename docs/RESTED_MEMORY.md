# 睡饱后的永久小纪念（2026-10-21）

## 体验

「永久纪念册 → 日常照顾」新增 **睡饱后的小小伸展**。记录一段真正恢复过体力、达到满格后由玩家主动叫醒的休息，和「轻轻说一声晚安」分开保存。卡片也会出现在「全部回忆」，仍用 A / B 翻页、C 返回。

只收藏已发生的事情，没有未解锁列表、额外金币、成长奖励、连续登录要求或新按键。文案不声称这是宠物历史上第一次睡饱，也提醒“不用每次都等到满格”。

## 记录条件

只在服务端成功执行明确的 `sleep` 起床动作时，同时检查：

1. 当前是 schema18 及以上的存档。
2. 当前 `sleepSession` 存在，代表已记录起点的这一段睡眠。
3. 该段已结算的 `energyRecovered > 0`。
4. 起床时实际体力等于 100，而不是整数显示四舍五入后的 100。

普通读取、刷新、服务重启、睡着自然到满都不记；刚入睡即起床、满体力入睡但没有实际恢复、尚未恢复满、只有旧版 `sleeping` 标记或导入后没有连续记录的睡眠都不记。已满但仍在睡觉时不会自动叫醒。

后续醒来只保留最早那张的时间和来源；体力再次下降不删除回忆。日记仍保留最近 30 条，淘汰日记不影响这张永久卡片。原睡眠恢复速度、有效休息习惯、自然成长、成年定型及 12 小时单次结算规则不变。

## 旧档、备份与校验

- schema17 → 18 只升级版本，不新增虚构条目、不改变已有记录或正在进行的游戏。已有完整 `sleepSession` 原样保留，可以在之后符合条件的明确起床时记下新纪念；缺失的旧睡眠记录不会倒推。迁移前由原事务保留快照。
- 新记忆种类为 `rested`，只保存原 `Memory` 结构的 `kind / at / source: shared`，不保存另一份睡眠数字。纪念册容量校验由 32 增为 33；schema17 不接受新种类，未知种类、重复条目、错误来源或多余专属字段照常拒绝。
- 已保存的卡片可正常导出、恢复和重启续读；导入不新增卡片，也不会保留活动睡眠的连续计数。重置新宠物不会继承旧纪念。
- 起床请求幂等重放不重复照顾或记忆；schema17 已缓存的旧起床回执即使升级返回格式，也不会补造新卡或改变原小结；睡眠意图冲突拒绝后不写卡片，非法导入不替换当前存档或留下新快照。与其他本地历史一样，合法 JSON 备份不是防篡改的在线证明。

## 验证方式

- `internal/game/rested_memory_test.go`：满格/未满/几乎满/原本已满/即时起床、单次结算上限、只读不记、无额外成长或资源、首条保留、日记淘汰、旧档已知/未知睡眠及非法卡片。另用合成的 album-only 夹具检验全部 33 张卡的种类与容量，以及旧版 32 张上限；不是完整存档或自然收集历史的证明。
- `internal/store/rested_memory_test.go`：独立临时 SQLite，schema17 原始快照、已满后的重启、幂等起床、备份恢复、拒绝重复导入不动存档/快照、重置、导入后未知睡眠及旧版幂等缓存不补造历史。
- `internal/httpapi/rested_memory_test.go`：真实 HTTP 处理器、受控服务时钟，四类睡眠、真实 409/400、重启、备份和回执不重放。
- `web/src/RestedMemory.test.tsx`：响应守卫、分类、卡片措辞、旧服务/无记录不造卡、历史卡片在低体力时仍可读、LCD 无新增操作控件。
- `scripts/check-rested-memory.mjs`：独立二进制/网页、临时库与随机端口，真实 Chrome 和自然经过的短睡眠。三阶段 × 桌面/320px/320px 短屏，手机为双倍根字号、高对比度、减少动态。先显式导入合法旧版近满体力初态，再真正入睡、结算到满、刷新和主动起床；不伪造时钟、恢复计数或响应。核对三键翻卡/返回、日期、资源不增加、文字不裁切/横溢、三键可达以及备份恢复后仍可读。

```sh
PIXELPET_TEST_BINARY=/absolute/isolated/pixelpet \
PIXELPET_TEST_WEB=/absolute/isolated/web \
PIXELPET_PLAYWRIGHT_MODULE=/absolute/playwright/index.mjs \
node scripts/check-rested-memory.mjs
```

不得指向玩家端口或共享构建；脚本在导入浏览器或启动服务前检查隔离构建，并自行创建数据库与监听端口。本轮数量与交叉回归结果见 [开发记录](PROGRESS.md)；自动化不等同于真人多日养成或实体手机验收。
