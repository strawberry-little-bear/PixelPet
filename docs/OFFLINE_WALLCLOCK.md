## 重跑与边界

先构建专用临时二进制，再执行（需要可用 Node）：

```sh
go build -o /tmp/pixelpet-wallclock ./cmd/pet
PIXELPET_TEST_BINARY=/tmp/pixelpet-wallclock node scripts/check-offline-wallclock.mjs
```

脚本只接收绝对二进制路径，不接收玩家 URL/数据库。默认真实等待 16 分钟；可用 `PIXELPET_WALL_WAIT_MS` 设为 16–60 分钟，不能缩短为假快速测试。日志给出临时产物目录，保留基线、各次响应、请求及服务日志。

这是**服务停止后的真实短时 API 验收**，不是实际关闭浏览器标签的人工测试，也不是自然多日成长、跨阶段或 12 小时上限的墙钟认证。后者仍由既有受控测试覆盖，真实长期体验继续待反馈。不改养成数值、后端、schema 或 A/B/C 操作。

## 新版明确入睡的真实停服验收（2026-10-20）

原六组中的睡眠由 schema1 的 `sleeping` 标志迁移而来，正确行为是没有入睡会话或整段起床回执；它们不能证明新版 `sleepSession` 在真实离开后仍完整。现在新增可选模式：

```sh
go build -o /tmp/pixelpet-wallclock ./cmd/pet
PIXELPET_TEST_BINARY=/tmp/pixelpet-wallclock node scripts/check-offline-wallclock.mjs --recorded-sleep
```

该模式保留正常导入来设置幼年 / 成长期 / 成年，但从**清醒**开始，经真实 `/api/action` 明确入睡，验证新会话从零记录后才关闭三个独立测试服务。真实等待至少16分钟，无轮询、心跳、改时或直接数据库操作，再换端口启动：

- 被动读取和主动回访均保留同一个入睡时刻；累计结算、恢复体力、休息习惯、睡眠成长的增量逐项对照实际服务端时间与需求变化。
- 起床才产生完整回执，统计从原始入睡到本次起床的整个区间，不只最后一次读取。成年睡眠成长为零。
- 起床本身不另外给成长或习惯；重复同一个起床请求保留同一回执，不再次切换睡眠或重播回访通知。
- 活动会话在起床后清除；小结仍只认领一次，再次重启不恢复旧睡眠或待读通知。原六组模式额外断言不为旧睡眠补造入睡历史。

这是新的**API真实短时离开**覆盖，不是新增养成玩法，不是自然养到成年、跨阶段、12小时上限、实体设备或浏览器后台认证。三键不变，测试不重启或部署玩家服务。浏览器展示沿用独立短睡的[进度](SLEEP_PROGRESS.md)与[起床小结](SLEEP_SUMMARY.md)验收，不能将两种证据混作同一趟16分钟浏览器游玩。
