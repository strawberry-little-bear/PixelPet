## 前端回归

此前两个通用同步测试文件的矩阵仍只有最初六款，本批新增16项、定向共90项通过，补齐寻宝：

- 普通读取发现另一页开局，退出旧阅读页并进入暂停画面，不自动探索。
- 新会话ID清除旧放弃确认与暂停菜单选择；同ID普通探索则保留主动确认/选择。
- 六次探索结束与提前找齐三件都撤销旧的「放弃未完成局」意图，必须再明确收好。
- 更旧revision的新局、终局、移除响应不能撤销当前确认；已同步终局后的帮助页不被普通读取挤走。
- 真实服务拒绝的过期放弃是「本次未执行」，不同于丢失响应的「可能已保存」。离线或旧版本恢复读取不结算、不重复提交；B读取成功后还要另一次B才收好。
- 延迟回访小结确认回复同时携带寻宝开局或终局时，按当前游戏路由，不用旧小结遮挡，不自动结算。

上述包含mock API与假时钟，不将其描述为真实断网、长时离开或自然养成验收。

## 真实Chrome脚本

`scripts/check-treasure-sync.mjs` 只启动自有临时SQLite、随机端口、隔离二进制和隔离前端，不接受玩家服务地址，不覆盖玩家存档或共享产物。复跑：

```sh
PIXELPET_TEST_BINARY=/absolute/isolated/pixelpet \
PIXELPET_TEST_WEB=/absolute/isolated/web \
PIXELPET_PLAYWRIGHT_MODULE=/absolute/playwright/index.mjs \
node scripts/check-treasure-sync.mjs
```

1200px/根字号14px与320px/根字号28px，两档各三组；小屏启用强制颜色，均减少动态效果。

1. **找齐三件**：观察页正在阅读成长手册，另一页三键开局；等真实15秒普通`POST /api/visit`，进入暂停。观察页主动打开放弃确认；另一页探索一格，普通同步保留确认；另一页找齐三件后，下一次同步撤销旧放弃，但不发奖励。观察页明确收好一次，另一页普通同步回小窝且不伪造本页回执。
2. **六次空地**：同样流程，实际探索六个空地；终局揭示不计找到，明确收好得3币而非6币，首次纪念只记一次。
3. **放弃冲突**：观察页停在旧放弃确认，测试只延迟其一条普通读取到达服务端；另一页找齐三件。观察页B发送带`X-PixelPet-Cancel-If: unfinished`的真实放弃，服务端真实409/`game_finished`。保持「放弃未执行」说明；释放未经修改的旧读取不能自动清掉这次拒绝。恢复时机身A/C保持禁用，对应键盘输入也不写入；B只GET核对，另一次B才收好。

每组继续验证另一页开下一局、新ID重置观察页旧菜单选择，B是继续探索而非误放弃；无自动探索、重复收好、重复产币或额外纪念。检查横向不溢出、仅原三个机身键、零浏览器运行异常，记录请求及终局截图。读真实服务地图来选择路线，不冒称真人盲玩。

### 明确边界

Headless Chrome的两个页面实测都为`visible`，本脚本因此只声称**双页面普通轮询**及受控的延迟读取/真实409恢复，不声称测过操作系统真实切后台、自然离线时长、实体手机或读屏。没有伪造成功响应或服务端错误；临时宠物由合法导入构造，不是自然养成。真实前后台暂停仍需既有组件回归及实体设备试玩补充。

验收脚本初次漏按重复开始卡的B，另一次误用Playwright点击禁用A/C：它会等待普通恢复读取将按钮重新启用，随后C是在新终局上明确收好，并不是自动结算。脚本已改为断言按钮禁用、直接发送键盘A/C，再独立按B核对；同时等延迟读取真实响应结束后才断言旧响应没有清掉拒绝。这些属于测试设置修正，不列为产品故障。恢复期间后续普通定时/返回读取仍可安全只读核对，不承诺只能由B触发读取。
