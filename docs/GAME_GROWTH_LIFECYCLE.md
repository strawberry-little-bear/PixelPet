# 七款小游戏与成长、离开及睡眠的交错回归（2026-10-20）

## 本批范围

新增 `internal/store/game_growth_lifecycle_test.go`，用七款游戏 × 完成/放弃的 **14条完整旅程**补足系统交错覆盖。本批未发现新的高置信度产品Bug，**只增强测试，不修改产品规则、数值、奖励、schema、旧档迁移或A/B/C操作**。

每条旅程从临时SQLite中的真实新蛋开始，以实际服务端命令孵化、开始游戏并产生部分进度；随后推进模拟服务端时钟，经过幼年、成长期、成年，再完成或放弃原局，继续照顾、睡眠、醒来及开始新局。不直接赋值需求、成长点、习惯、阶段、棋盘或奖励。

## 保护的组合路径

- 每次成功命令、读取和数据库重开：返回状态通过校验，且与SQLite实际保存的状态一致；身份/存档代次保持，成长及习惯不倒退。
- 游戏未结束时拒绝喂食、清洁、睡眠和另开游戏；即使拒绝前发生了自然时间结算，失败事务也不能部分提交。
- 一次离开48小时只结算12小时；不同间隔后续访问分别按各自上限结算，不声称多次访问与一次离开等价。
- 未结束游戏跨两个成长阶段，棋盘、分数、候选鱼、等待累计、路线、发现及游戏ID均不变；四款有时钟租约的游戏确实暂停，数据库重开后仍暂停。不因离开而补跑或提前发游戏奖励。
- 成年时间、形态及冻结的判定依据保持不变。长期未照顾的真实历史形成随和形态，不通过近门槛夹具跳过成长过程。
- 原局明确结束后，只对符合既有门槛的成绩记录一次照顾习惯、金币及共同游戏经历；成年不再加成长点。放弃和不合格低分不发奖励。
- 同请求重试、读取及数据库重开不重复结算。新局使用新ID，旧请求缓存重放不改变新局，用新请求ID提交旧局动作会拒绝。
- 游戏结束后实际喂食、清洁、入睡，模拟7小时15分睡眠恢复满体力并积累休息习惯；数据库重开后真实起床仍有整段睡眠回执，不给成年加成长点。
- 游戏中和睡眠中的JSON备份分别导入另一临时安装：保留需求、成长、冻结依据、钱包、照顾次数、图鉴、纪念及共同游戏历史，但按设计清除未结束游戏和本次睡眠连续会话；保留睡眠状态，不伪造醒来回执，源数据库不变。

- 14条旅程重复 **20次，共280条**全部通过。
- Go无缓存全量 `-race`、`vet` 和独立二进制构建通过。

- 在 `/tmp` 的四份源码副本中分别注入受控故障：禁用贪吃蛇离开暂停、离开上限改为48小时、导入错误保留本次睡眠连续会话、禁用请求重放缓存。**四项均被新测试的预期断言拦截**，不是工作树或玩家服务里的真实产品故障。
- 方块首轮用例误把运行中的落底当作合法操作，已按实际暂停菜单规则修正测试；没有为测试改产品规则。

这是**模拟时间的服务端组合回归**，不是自然多日真人长玩。连连看/挖宝读取实际生成的合法地图来选择命令，不代表人类难度验收；贪吃蛇直行撞墙、方块固定列堆满，均只覆盖不满足陪伴门槛的低分终局，不能替代既有高分及全部玩法分支测试。自然成长完整经过两个阶段，但本批不声称覆盖四种成年形态。
