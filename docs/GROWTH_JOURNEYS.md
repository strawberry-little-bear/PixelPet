# 从新蛋开始的完整成长回归（2026-10-19）

## 为什么补这一批

已有测试包含成长积分、形态条件、离线边界与临近成年夹具，但「设置好成长点数再做一次照顾」不足以证明新宠物能靠实际操作走完整个旅程。本批增加跨存储的持久回归，不新增玩法，也没有为了测试修改养成参数。现有规则在这批场景中通过，未发现需要修复的产品缺陷。

持久入口：`internal/store/growth_journey_test.go`，`TestGrowthJourneysFromHatchThroughCareAbsenceAndRestore`。一个顶层测试、10 个角色分组、**40 条命名旅程**，不是新增 40 个独立顶层测试或 40 个功能。

## 实际覆盖的链路

每条旅程都在 `t.TempDir()` 创建 SQLite，从新蛋选择对应角色并孵化：

1. 不直接赋值需求、成长点数、习惯、阶段、形态或里程碑日期；只推进显式传给存储层的模拟时间，调用正常 Visit / DoForGeneration / 导入接口。
2. 先离开 48 小时。独立数值预期核对清醒需求只结算 12 小时（44 / 50 / 66 / 61），成长跟踪 12 小时、12.255 点，照顾次数仍为 0；回访的真实离开区间仍为 48 小时。
3. 将仍在幼年的实际 JSON 导入另一临时安装，关闭重开，继续同一旅程；首次进入成长期时再导出、导入、重开并接着照顾。不是只比较一次导入结果后继续养原库。
4. 推进至孵化后 216 小时：按策略选择真实喂食、清洁、入睡/叫醒与五次接星星输入。每个成功响应都校验存档有效、身份不变、需求/成长合法、习惯及成长记录不倒退；Visit 不冒充照顾或产生照顾回执。
5. 在第 120 小时关闭并重开当前数据库，核对需求、成长、日记、纪念和安装身份完全保留。每条旅程最终必须实际经历幼年 → 成长期 → 成年，而非替换阶段字段。
6. 核对成年快照对应真实成年时刻，非返回时刻；成年日期、形态与定型依据随后不可改写。相遇/成长/成年、相识 1 天/7 天的纪念均只保留一份。
7. 成年后再次便携恢复并继续操作；一次真实喂食后回放同一 requestId 两次，只读核对整份存档不变。实际游戏（有体力时）和 48 小时睡眠仍能留下照顾记录，但不能改成年结果；最后再次重启、导出/导入并重开。

四种策略（每种覆盖全部十只角色）：

| 测试策略 | 具体安排 | 本批核对结果 |
| --- | --- | --- |
| unattended | 开头长离开后每 12 小时回来，不喂食/洗澡/玩耍/睡觉，直到检查完成年 | 自在型，需求可到零但仍成长、无永久死亡 |
| quiet | 每小时查看；饱食 ≤70 喂食、清洁 ≤65 洗澡；体力 ≤45 入睡、恢复至 ≥99 再叫醒；不陪玩 | 恬静型，早于无人照顾组成年 |
| playful | 同样按需求照顾，清醒且有体力时每逢偶数小时完成一局接星星 | 活力型，早于无人照顾组成年 |
| balanced | 同样按需求照顾，当陪玩习惯低于（清洁 + 休息）/2 时完成一局接星星 | 均衡型，早于无人照顾组成年 |

这些是可复查的测试输入，不是选择成年形态的新菜单、普遍养成时长承诺或鼓励反复刷按键的攻略。实际玩家会有不同的需求、习惯、游戏成绩、查看与睡眠安排。

## 验证与边界

- 针对性 40 条旅程全部通过；Go 全量无缓存 `test -race -count=1 ./...`、`vet ./...`、构建通过。这些用例随既有后端 CI 自动运行，不依赖临时浏览器脚本。
- 前端既有 **1477 项 / 70 文件**、TypeScript、生产构建及既有节奏算术 **6 项**通过；没有新增前端用例或节奏小游戏。
- 本批只改测试与文档，无界面改动，未新增截图、浏览器验收或 HTTP 全链路认证。接星星调用实际存储层动作，但不把这些调用声称为键盘/触摸试玩。
- 显式模拟约 9 天的成长安排和成年后 48 小时，不修改系统时钟，也不实际等待多日。不能替代真实长时间挂机、移动系统后台行为、十只动画观感或真人反馈。其他小游戏、旧 schema 迁移沿用各自已有专项回归，不冒称本批新覆盖。
- 本批无生产 Go/前端源码、schema 12、数值、奖励、六游戏或 A/B/C 改动。测试没有直接 SQL 造阶段或导入覆盖玩家数据。
