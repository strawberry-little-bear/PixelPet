# 小店、钱包与装扮回复保护（2026-10-20）

## 复现与边界

在隔离服务中先正常进入小店的全部物品，再将下一次真实读取回复的 `shop.catalog` 人工替换为 `[null]`。旧独立构建会在选择物品时读取空条目的 `id`，Chrome 报 `Cannot read properties of null (reading 'id')`，React画面退出；没有可用的三键核对界面。

这是**异常响应下的显示安全缺口**，不声称正常服务端会产生这个目录，也不声称玩家存档已损坏。早先小游戏／成长等回复保护仍保留，本批只补尚未保护的钱包、装备与小店模型。

## 修复

`validCoreResponse` 在接受回复前检查：

- 可选 `state.economy`：金币和已用额度为非负安全整数，问候／游戏时间可安全格式化；拥有列表若提供非空值必须为字符串数组，装备必须为对象；基础两槽为字符串，旧版本可省略墙纸／地板。
- 可选 `shop`：问候和共享额度为非负安全整数，可省略旧版本没有的钱包上限；目录若提供非空值必须为数组，每件为可显示的字符串字段、受支持槽位与非负整数价格。
- 不限制服务端合法的新物品ID，不硬编码当前价格、金币上限或每日额度，不在客户端重新判定所有权一致性、存档时间顺序或经济规则。测试保留未来物品、不同价格／上限及未来保存时间，不能把显示保护写成第二套存档校验。

不安全读取沿用只读重连，保留最后一次可读状态；不安全写回复沿用「结果还未确认，可能已经保存」，B只读核对，不能自动重买、补币或播报成功。没有新的错误按钮或LCD玩法控件。

### 合法空列表与旧服务

Go的nil空切片和旧服务省略列表不能与损坏对象混为一谈。允许 `owned: null`／省略／`[]`，四处拥有检查使用可选读取：分类筛选、物品显示、确认报价及三键购买控制。只对真正缺失的列表解释为没有物品，不把对象、字符串或坏数组伪装成空拥有列表，也不改写原回复或存档。

省略／null的钱包和小店继续走原「小店还没开门」兼容说明；墙纸、地板和 `maxCoins` 的旧字段缺省保留。目录缺失／null／空数组安全显示为空，不凭空补服务端目录。当前正式导入会复制并规范空拥有切片，浏览器的null／省略情况是明确的兼容回复夹具，不冒称正常导入已产生故障。

不改Go生产代码、schema17、资源、成长、奖励、价格、目录、三键协议或旧档；屏幕未增加可点击玩法控件。

## 复跑

```sh
PIXELPET_TEST_BINARY=/absolute/temp/pixelpet \
PIXELPET_TEST_WEB=/absolute/temp/web \
PIXELPET_PLAYWRIGHT_MODULE=/absolute/node_modules/playwright/index.mjs \

```
