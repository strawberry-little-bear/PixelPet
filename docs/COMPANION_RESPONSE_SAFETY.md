# 共同游戏记录响应保护（2026-10-19）

## 可复现问题

基础响应校验原先忽略可选的 `state.companion`。HTTP 200 且 JSON 完整并不保证手册能展示：缺失兴趣数组会在 `map` / `find` 抛错，兴趣点为负数、小数或超过上限可能使圆点 `repeat` 抛错，最近游戏日期超出 Date 范围会使 `toISOString` 抛错。

现在在接受响应前检查：

- 已提供的共同游戏记录必须是对象，起始时间可显示，兴趣为数组。
- 兴趣项属于现有六个游戏，点数为 0–5 的安全整数，最后记录时间可显示。
- 最近一次记录如提供，必须有非空字符串 ID、已知游戏和可显示时间。
- 缺失 / null 的旧记录、空或部分但可安全展示的兴趣数组仍兼容，不补造历史。

只校验展示安全形状；不在浏览器重复服务端的时间先后、积分资格、顺序及迁移规则。没有新增响应字段，不把可选历史异常冒称玩家数据库损坏。

异常读取进入原有连接恢复；照顾请求的异常成功回复仍属“结果未知”，B 只 GET state 核对，A/C 不重发，不追加照顾、奖励、游戏经历或补播成功提示。正常已保存的最近游戏在恢复后可查看，但不变成本次新经历。

## 重跑

使用自己的临时服务二进制与可用 Node / Playwright：

```sh
PIXELPET_TEST_BINARY=/tmp/pixelpet-test node scripts/check-companion-response.mjs
```

需要时设置 `PIXELPET_PLAYWRIGHT_MODULE` 为 Playwright 的绝对模块路径。脚本自己创建数据库和随机端口，结束后关闭自己的服务/浏览器；不接收玩家 URL 或数据库。

后端、schema 12、成长数值、奖励及 A/B/C 路径不变。玩家库与原进程保留，未刷新玩家标签。构建更新共享 `web/dist`，不等于重启或部署原后端。
