# 可见窗口失焦后的访问记录（2026-10-20）

## 复现与根因

窗口切到其他应用后，网页可能仍然可见，`document.hidden` 仍为 `false`。原定时刷新只检查可见性，因此窗口收到真正的 `blur` 后，仍每 15 秒发送 `/api/visit`。服务端将它正确视作前台访问，持续更新访问基线，因而无法将这段离开计入回访间隔。

另有两个相关竞态：失焦前已经发出的读取完成后可能自动认领小结；已经认领的回复迟到时可能在失焦窗口自动展示。最初新增的七项组件测试在旧实现下五项失败、两项通过，日志 `/tmp/pet-window-presence-red.log`。这是独立复现的问题，不代表用户之前那轮试玩发现了它。

## 修复边界

- 复用同步窗口焦点标记，覆盖定时刷新和小游戏运行许可。真正窗口 `blur` 后不再发新的定时读取／访问；元素间冒泡的焦点事件不算离开。
- 窗口可见且收到 `focus` 时立即同步，不等待下一次轮询；忙碌或有旧读取时，沿用原有合并补读，不重放照顾或游戏动作。
- 自动认领和展示同时检查可见性与窗口焦点。失焦前已经发出的请求仍可保存并更新权威状态，不假装撤销服务端操作；其迟到回复不自动弹出，也不在再次聚焦时补播。已保存的小结仍可用 A/B/C 从菜单重看。
- **可见阅读计时与访问在场感分开**：仍可见的照顾反馈不会因失焦／聚焦而暂停或重置阅读时长。全量测试曾检出将两者共用一个开关的连带影响，最终修复没有放宽原断言。
- 隐藏页面仍不轮询，小游戏回来后仍需明确继续；不新增 LCD 点击控件。后端结算、12 小时单次上限、三阶段、奖励、schema17 与旧档均不变。

这是对浏览器实际派发的窗口／可见性事件的处理，不是用焦点来判断人的注意力。初次加载策略未在本批重做；浏览器不派发失焦事件、原生 App 切换差异以及实体手机后台仍需人工体验。其他仍在前台的游戏窗口会继续作为该存档的真实访问，不承诺仅一个窗口离开就产生小结。

## 重跑

先使用可用的 Node、Go、Python3（sqlite3 标准库）、Playwright 和 Chrome，构建到仓库外的独立目录：

```sh
mkdir -p /tmp/pet-window-presence-recheck
.tools/go/bin/go build -o /tmp/pet-window-presence-recheck/pixelpet ./cmd/pet
(cd web && ./node_modules/.bin/tsc --noEmit && ./node_modules/.bin/vite build --outDir /tmp/pet-window-presence-recheck/web)
PIXELPET_TEST_BINARY=/tmp/pet-window-presence-recheck/pixelpet \
PIXELPET_TEST_WEB=/tmp/pet-window-presence-recheck/web \
node scripts/check-window-presence.mjs
```

需要时设置 `PIXELPET_PLAYWRIGHT_MODULE` 和 `PIXELPET_PYTHON`。脚本先验证独立构建，只接受自己创建的临时库和随机端口，不接收玩家 URL／数据库参数，结束后只关闭自己的服务和浏览器。
