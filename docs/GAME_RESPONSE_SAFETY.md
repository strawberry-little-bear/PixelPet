# 小游戏回复的显示安全保护

日期：2026-10-20。只增强读取异常成功回复时的保护，不改正常玩法、三键、后端、schema、奖励或成长。

## 复现与边界

在独立临时服务创建真实连连看局，仅将浏览器收到的成功回复中的 `tiles.board` 改为 `null`。旧构建产生 `Cannot read properties of null (reading 'map')`，页面为空，也没有恢复入口。独立 API 新回归在旧代码下 **82 项失败／15 项通过**。

这是**人工损坏 HTTP 回复的防白屏缺口**。没有向数据库写坏模型，也没有证据表明正常服务会生成这些数据；不能据此诊断玩家存档损坏。

## 处理

- 所提供的 game 必须是对象，游戏类别可识别，公共时间、轮数、分数、节拍和可选 id 可安全显示。旧接星星缺少 kind／id，以及没有 game 的旧回复仍兼容。
- 连连看：棋盘、选牌位置、已配对数和重排数。
- 贪吃蛇：有限长度的身体、格点坐标、食物、方向、进度、时间、暂停和终局字段。
- 方块：棋盘、预告块、计数、时间、暂停和终局；提供活动块时限制类型、旋转和坐标，避免图形／落点循环异常。合法终局的活动块省略／null 仍接受。
- 散步：路线、纪念物、步数、姿势、计数、时间和暂停。
- 钓鱼 catches、寻宝布局沿用既有保护。钓鱼空渔获省略／null 仍兼容；不是本次扩展所有钓鱼字段的深层校验。
- 一些 hook 会读取非当前类别的已提供模型，因此也检查已提供的上述四种模型，不凭它们推断游戏类别。

所有校验在应用响应前执行。不补空棋盘、不猜进度、不重启游戏、不伪造成功；坏读回复进入连接恢复，坏写回复仍是「可能已经保存」。A/C 不执行新写入，B 只读核对；第二次坏读不解锁，权威读取成功后返回已保存的原局，不自动续玩、重发、补奖或重播成功动画。

这里只检查前端可使用的形状和有限范围，不检查身体连通、棋盘可解性、积分真实性、计数对应关系或时间先后；服务端仍负责完整存档校验、迁移与业务规则。其他可选对象也不因此成为完整深层校验。

