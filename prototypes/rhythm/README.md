# 节奏拍手 · 独立无奖励原型

这不是第八款正式游戏。它只验证三键交互和时序观测，不读取正式游戏代码、数据库、存档，不发金币/成长/兴趣/纪念，不部署或连接玩家服务。

## 启动

在仓库根目录，使用 Node 24+：

```sh
node prototypes/rhythm/server.mjs
```

终端输出 JSON 内的 `url`，在浏览器打开即可。只监听 `127.0.0.1`，默认随机端口；退出用 Ctrl+C。默认会话只在实验服务内存中，闲置十分钟失效，最多32个；同一标签刷新会核对本局并暂停，不重开或恢复旧拍。

- A 左侧圆形 / B 右侧三角，预告结束再回应；C 暂停。
- 暂停时 A 切换继续/重开，B 选择，C 继续。选择重开先显示本局观测数量和清空后果，再按一次 B 才清空；A / C 取消并保持暂停。完成后按 B 也先确认，不直接清空十二次观测。
- 12次回应结束，不发奖。无需音频；形状与文字可区分方向，支持减少动态和强制颜色。方向与准备／回应阶段在服务端回复被接受时一起更新，不等待下一动画帧；新一拍不会沿用上一拍的「现在回应」。等待回复时改为「正在核对」，不会继续邀请 A/B 回应。
- 阶段提示包含当前应按的 A/B 和形状，通过独立 `status` 区域作离散播报；普通进度帧与不消耗本拍的预告输入不重复改写阶段文字。这里验证的是可访问性语义与 DOM 更新，未证明真人读屏能在实验窗口内听完或回应。
- 预告中按键不消耗；按住不连发；忙碌时不排队输入。聚焦机身 A / B / C 后，Enter / 空格在首次按下时执行该键，重复按下与空格松开不追加操作；其他位置不新增 Enter / 空格全局快捷键。输入法组合与 Ctrl / Alt / Meta 组合不作为玩法输入。
- 失焦、隐藏、断线、帧间隔超过1000ms或估计截止时暂停，回来必须手动继续；失败输入不自动重发。
- **输入先于下一次绘制时也检查停拍**：长卡顿后排队的 A/B，或已超过估计截止的按键，不会因为旧画面仍显示「现在回应」而发送旧拍回应；改为中性暂停，明确继续后才接收新拍。阈值与动画帧检查一致，不延长窗口。已经发出的请求仍按原协议处理，服务端继续如实记录网络晚到观测，不据此判玩家失误。

## 刷新与结果未知时的恢复

- 同一标签用 `sessionStorage` 只保存实验会话 ID，不保存回应、客户端成绩、时间锚点或旧页面操作凭据；服务端记录才是观测依据。不使用正式存档、SQLite、账号或跨设备同步。
- 刷新发送独立 `recover`：保留已确认的观测和拍序，清除旧拍，回到暂停；完成的12次观测保持完成，不自动重开。B / C 明确继续才产生新拍，只有明确重开会清空本局观测。
- 离开页面（`pagehide`）会立即停住本地提示、撤销重开确认并使所有在途回复失效；页面处于离开状态时，三键、失焦和断线事件不会再发请求。不依赖离页请求成功，也不在离页时尝试补写结果；实验服务可能仍保留旧拍，下一次手动核对会清除它。
- 浏览器复用缓存页面（`pageshow.persisted`）后，先显示「B / C 手动核对本局并暂停」，核对后再单独继续。迟到的继续／回应／暂停／重开／核对回复都不能恢复旧拍、重开或自动重试。完整历史重载继续沿用同标签刷新协议。若创建会话的回复尚未确认、没有可用会话指针，不猜测旧会话；明确按 B / C 才新建暂停练习。
- 每次核对更换页面操作凭据（lease），普通操作同时校验凭据、单调请求ID及拍序。恢复先到，旧页面迟到的继续／回应／重开都被拒绝；回应先到，保留一次观测后暂停。不是重发未知输入，也不是用客户端自报结果补写。
- 连接失败不自动创建、循环核对或继续。B / C 先核对暂停，再按一次才继续。会话已失效则说明旧观测无法恢复，清除这个实验指针；再明确按 B / C 才新建暂停练习。
- 重开确认只属于当前页面：刷新、失焦、隐藏或断线会取消这次确认，不记住待执行的重开。确认请求的回复丢失时仍按原核对协议处理，不自动重发重开，也不自动继续。
- 禁用或无法使用浏览器会话存储时，当前页仍可练习，但刷新不能定位旧会话。新标签通常独立；浏览器复制标签可能继承指针，核对会使旧页凭据失效，旧页必须重新核对。**这不是多端无缝续玩、永久持久化或生产级接入。**
- 默认内存模式下，服务重启或闲置失效仍会丢失实验观测。更换随机端口是新站点，原端口的会话指针不会自动迁移。显式快照模式的重启恢复见下节；正式游戏的持久化、迁移、权威结算与幂等方案仍需独立完成。

## 可选的实验快照与服务重启恢复

默认不写文件。需要跨实验服务重启保留观测时，显式选择**仓库外的独立文件和固定端口**，例如：

```sh
mkdir -p /tmp/pixelpet-rhythm-lab
PIXELPET_RHYTHM_PORT=18120 \
PIXELPET_RHYTHM_STORE=/tmp/pixelpet-rhythm-lab/observations.json \
node prototypes/rhythm/server.mjs
```

启动 JSON 的 `persistent: true` 表示快照模式已就绪；再次使用相同路径、端口启动。目录必须已经存在。`/tmp` 只是隔离实验示例，系统可能清理它，不是永久档案。不要使用正式服务端口、玩家数据库或游戏备份路径。

- 只保存实验会话 ID、拍序、服务端已接收的观测；不保存实时提示、目标时间、旧页面凭据或请求 ID。未完成的练习重启后暂停，完成的十二次观测保持完成。同一标签刷新或按 B / C 手动核对，再单独继续；不补跑停机时间或重发未知回应。
- 状态变化串行提交，快照写入临时文件、同步文件、替换并同步目录后才返回成功。写入失败或结果未知时返回 503，并停止后续操作；修复文件系统问题、重启实验服务后手动核对。恢复可能看到最后一次请求已保存，也可能没有，不能据此自动重发。
- 快照绑定固定端口，服务先独占该端口再打开文件；首次用排他创建认领文件。同端口第二个服务或不同端口复用同一快照都会拒绝启动，不改变已有记录。不要在运行中手工编辑、替换快照或同时用其他程序写它。
- 拒绝仓库内路径（包括经目录符号链接进入仓库）、文件符号链接、硬链接、无关／损坏／新版／超过 256 KiB 的文件，不覆盖它们。文件格式版本为实验专用的 `pixelpet-rhythm-observations` v1，与正式存档无关。首次空文件初始化中断可能留下不完整文件，下一次启动同样拒绝，不猜测恢复。
- 运行中仍按单调经过时间判定十分钟闲置，过期删除也会保存，最多 32 局。**重启后从启动时重新给已保存会话十分钟核对期**；不持久化跨进程时钟或声称精确计算停机闲置。重启不会找回已经保存删除的过期记录。
- 当前在 macOS / Node 24 验证文件与目录同步。文件系统不支持这些操作时拒绝启用或停止写入，不静默降级成“已保存”。未验证断电、实体设备后台、多机共享目录或跨平台迁移，不是正式存档系统。

## 实验参数与边界

```sh
PIXELPET_RHYTHM_UP_MS=250 PIXELPET_RHYTHM_DOWN_MS=50 \
PIXELPET_RHYTHM_JITTER_MS=200 node prototypes/rhythm/server.mjs
```

`PIXELPET_RHYTHM_PORT` 可显式指定端口；请勿占用玩家服务端口。UP/DOWN各0–2000ms，JITTER为0–1000ms、交替添加到上下行，均为合成延迟，不代表真实公网。全局请求序号决定交替模式，不是网络丢包模型。

原型服务给拍序、目标/截止和服务时间；客户端用 `performance.now()` 推进，以RTT中点**估计**服务器时钟。非对称延迟下有误差；实测RTT超过600ms则中性暂停，而不是仍能公平精确打拍。预告1800ms、观测窗口早250ms/晚1800ms、帧间隔1000ms均为实验值，不是正式游戏参数。

服务端的拍序计时、服务时间锚点和十分钟闲置判断统一使用 `performance.timeOrigin + performance.now()`，不会随进程运行中的墙上时钟校正跳变。`serverTime` 是这个固定时基的同步锚点，不能当作校正后的日历时间。独立 HTTP 回归用子进程预加载夹具分别控制墙上时间和经过时间，覆盖前跳、回拨、观测保留、恢复凭据和闲置边界；不修改系统时间，也不代表实体设备休眠计时或公网公平性验收。

只读观测中的“早到/窗口内/晚到”表示**服务端收到请求相对目标的偏差**，不是玩家命中/失误。错误方向也如实记录，不据此评分。序号防重复/旧拍，单调请求ID保证后来暂停压住先发却迟到的继续/回应；客户端另丢弃过期回复。暂停先到则不消费旧回应，回应先到则保留一次观测后暂停，不撤销已到达观测。

这不是生产级协议：可选文件仅保存独立实验观测，没有正式存档持久化/账号/多端无缝续玩/奖励结算。未来接入前，仍需验证真实设备和网络、低帧率、系统前后台及玩家舒适度，确定公平规则，再独立设计服务端权威结算、幂等、迁移和七款回归。十只宠物的真实爪/翼/鳍动作也未实现。不把通用实验符号当宠物动画交付。

## 浏览器时序观测

除了通过／失败验收，可用专门脚本记录实际原型的时序：

```sh
PIXELPET_PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs \
node scripts/measure-rhythm-timing.mjs
```

脚本只启动自己的随机端口、内存模式实验服务与全新 Chrome 上下文，不接受已有服务地址，不读取正式数据库或共享构建。每组结束关闭页面和实验进程，JSON 报告写到系统临时目录；不保存实验凭据。运行需要本机 Chrome 和 Playwright。

八组包括本地回环、100ms 对称延迟、两个方向的 300ms 非对称延迟、交替上下行抖动、至少 200ms 的受控动画帧间隔与触摸输入，以及 800ms 往返／超过 1000ms 帧间隔的保护性暂停。前六组各回应三拍后明确暂停，后两组核对零回应、一次保护性暂停和不自动续玩；同时检查实际配置、延迟生效、三键和无正式 API 请求。

每拍记录提示文本切换相对客户端估计目标的偏差、原生输入距提示的间隔、输入到请求的间隔、实测往返耗时和服务端收到回应相对目标的偏差。自动化在观察到回应提示后等待 200ms 再输入，调度和触摸动作还会增加耗时，报告保留实际间隔；**200ms 不是玩家反应速度假设，三拍也不是成功率样本**。

报告还保留从发拍回复到回应回复的服务端／浏览器各自经过时间，以及两者之差。差值也包含下行变化和调度，不能单凭它诊断时钟漂移；当绝对差值超过这两次 RTT 之和再加 100ms 时，`elapsedWarnings` 标记相应拍序，便于调查。这个标记只是保守的异常提示，不是公平窗口或新的玩法阈值。`passed` 只代表交互、请求次数及暂停等断言通过，**有晚到或经过时间警示时仍原样保留，不能把八组断言通过写成公平性通过**；失败组另存页面状态和不含凭据的请求诊断。

这里观测的是 DOM 文本变化，不是屏幕实际发光时刻；延迟由实验服务注入，慢帧由浏览器回调包装控制，触摸由 Chrome 自动化发出。它能对照当前客户端与协议的实际表现，不能替代实体手机、真人读屏、系统后台、真实网络或公平规则验收。服务端的收包分类继续只是观测，不给命中分数；RTT 中点仍无法证明单程延迟，上一拍的往返也不能保证下一拍网络相同。历史算术模型见[公平性评估](../../docs/RHYTHM_EVALUATION.md)，不把两种结果混用。

## 复跑

```sh
node --test prototypes/rhythm/*.test.mjs
# 已安装Playwright及Chrome；若模块不在默认路径，设置绝对模块路径。
PIXELPET_PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs \
node scripts/check-rhythm-prototype.mjs
# 只重跑真实实验服务重启验收：追加 --restart-only
```

协议、HTTP及客户端事件顺序测试可在CI运行，Chrome验收需显式运行。客户端测试用受控单调时钟／简化DOM验证输入先于动画帧、估计截止与RTT边界，不是浏览器或真实网络测量。Chrome脚本自行分配隔离端口服务、独立浏览器上下文，结果和截图写系统临时目录，退出只关闭自己的进程。无可配置玩家URL/数据库。

自动化包含真实等待12拍、键盘/模拟触摸、合成0/100/300/800ms往返、非对称和交替抖动、在途暂停、断线手动恢复、刷新、320px双倍文字、减少动态、强制颜色。脚本派发的blur/visibility事件不等于真实系统切后台，触摸模拟不等于实体手机，合成延迟也不证明公网公平。

Chrome另覆盖同局刷新、完成后刷新、已被真实服务接收但丢失回执的回应、恢复请求失败及失效指针的明确新建；失效指针是构造输入，不冒充真实等待十分钟或实际重启服务。

Chrome另覆盖真实阻塞主线程1101ms后、下一动画帧之前同步派发 A/B 键盘／机身按钮事件，确认不发送旧回应；这是人为控制的事件顺序，不冒充实体键盘、触摸硬件或系统调度认证。正常三键、12拍、手动恢复及合成网络场景继续交叉回归。

Chrome另覆盖聚焦机身键后的 Enter／空格重复 keydown 与松开：A 选项只切换一次、B 重开不紧接继续、C 暂停／继续只执行一次，跨到下一实时提示也不补录仍按住的回应；LCD 之外的无关文字焦点不触发玩法。这里使用浏览器自动化键盘输入，不等于实体键盘、所有浏览器或系统输入法验收；输入法／修饰键保护另用受控事件单测。

Chrome另覆盖重开确认：完成十二次观测后取消保留全部记录，暂停中取消不发请求；320px双倍文字／强制颜色／模拟触摸可阅读确认并取消，刷新只恢复观测而不恢复确认。真实实验服务接受重开后丢失回复且中性暂停失败时，只有明确核对才读取已清空的暂停状态，不重发重开；模拟失焦会取消旧确认。这些仍是隔离原型证据，不是正式存档或实体设备验收。

Chrome另覆盖手动派发 `pagehide/pageshow.persisted`、真实实验服务已接收但延迟交付的继续／回应／重开回复，以及 320px 双倍文字下的核对提示和模拟触摸。另做真实离页后后退，结果记录浏览器实际选择的是缓存复用还是完整历史重载；完整重载不算缓存复用验收。受控客户端测试还覆盖在途暂停／核对／创建、已完成十二次观测与旧重开确认。派发事件只证明该事件顺序下的防护，不等于真实 BFCache、实体手机后台或系统冻结验收。

Chrome另用受控 RAF 调度按约 200ms 间隔送达动画帧，同时保留真实 HTTP、DOM 和单调时间：核对首拍与连续相同方向的新拍在下一帧前已进入正确准备状态，阶段文字不随普通进度帧改写，在途回应的核对状态可被 C 暂停。覆盖桌面键盘与 320px 双倍字号／减少动态／强制颜色／模拟触摸，全程不使用音频。单测另覆盖 500ms 帧间隔、等待中的多余 A/B 和暂停后的迟到回复。这是人工调度下的一致性证据，不等于实体低性能设备、真人读屏反应、时钟同步精度或公网公平性验收。

Chrome另覆盖真正强制结束实验服务、相同固定端口重启、同一标签刷新核对：桌面与 320×380 双倍字号／减少动态／强制颜色／模拟触摸均保留已接收观测，清除旧拍并暂停，取消重开不写入，明确继续才产生新拍。快照和端口由脚本隔离分配，不接受玩家 URL 或文件路径。HTTP 测试另覆盖完成十二次、已接受但回复丢失、写入故障、并发认领／操作顺序、过期删除和损坏文件拒绝；进程强制退出不等于断电验收。
